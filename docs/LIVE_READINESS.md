# 실거래 전환까지 남은 단계

2026-11-10 기준 소프트웨어 개발·검증 현황이다. **실거래 시작일은 아직 확정할 수 없다.** 추가 개발과 실제 장중 검증은 보수적으로 수 주 단위로 계획한다. 이는 작업 범위에 근거한 일정 추정이며 실제 체결·장애 복구 결과와 사용할 전략의 결정에 따라 달라진다. 현재 live 설정은 계속 거부하며 실주문 API를 구현하거나 실행하지 않았다.

## 현재 위치

- 읽기 전용 KR/US 연동·전략/백테스트·리스크/원장·Paper 실행기·대시보드와 로컬 운영 기반은 구현했다.
- 실제 KR/US 유한 Paper는 60 tick 종료·원장 보존을 확인했지만 의도/체결 0건이었다. 실제 시세에서 매수→매도·비용·원가 경로는 미검증이다.
- MA 5/20은 시스템 검증용이다. 실거래에 사용할 전략은 확정되지 않았고 과거 연구 결과만으로 채택하지 않았다.
- [일반 정규장 유한 관측 감독](REGULAR_OBSERVATION_SUPERVISION.md)을 구현했으나 기존 미확인 예약 처리와 실제 실행 승인은 별개다.

11월 10일에는 [기존 5/20·1주 설정의 합성 원장/장애 복구](PAPER_FIXED_SETTINGS_VALIDATION.md)를 검증했다. 실제 시세 체결 검증을 대체하지 않으며, 독립 종료 근거 없는 예약은 [별도 정책 결정](PAPER_RESERVATION_POLICY_REVIEW_2026_11_10.md)이 필요하다.

## 전환 전에 완료할 일

| 순서 | 작업                             | 완료 기준                                                                                                                              |
| ---- | -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 기존 예약의 증거/처리 정책 검토  | 원본 보존·독립 근거·적용 범위를 검토하고 실제 실행 경로의 불확실성을 해소. 소급 증거/근거 없는 예외 금지                               |
| 2    | 실제 시세 Paper의 주문/체결 경로 | 기존 설정과 유한 창 안에서 발생한 신호·의도·예약·체결·비용·현금/소유권/원가를 연결. 신호가 없으면 미검증 유지                          |
| 3    | Paper 운영 회복 검증             | 정지·취소·API 지연/실패·데이터 만료·재시작 복구·loss carry·수동 보유 보호를 확인. 실제 운영 증거와 합성 회귀 검사를 구분               |
| 4    | 운용 전략과 범위 결정            | 전략/종목·실제 계좌·투자금/주문·손실 한도·운영 시간·중단 기준을 사용자가 검토·확정                                                     |
| 5    | 별도 실주문 연동 개발            | 최신 공식 Toss 명세/지원 범위 확인 후 인증·주문/조회/정정/취소·체결 동기화 구현. 의도 선기록·중복 방지·불확실 응답/부분 체결/복구 검증 |
| 6    | 명시적 소액·감시 전환            | Paper/live 원장과 권한 분리, 이중 활성화·긴급 정지·관측/정합성 검사를 검토하고 별도 사용자 승인 범위 안에서만 시작                     |

2번은 매일 한 번 더 기다리면 반드시 완료되는 단계가 아니다. 현 전략/유한 창에 신호가 생기지 않을 수 있다. 그 경우 종료 증거를 보존하고 실제 검증 목표·시나리오를 다시 검토하며 전략이나 한도를 임의로 바꿔 체결을 만들지 않는다. 부분 체결은 현재 1주/최대 체결 1주 설정으로 억지 재현하지 않고 합성 검사와 향후 실주문 adapter의 상태 동기화 검증으로 구분한다.

현재 작업은 1–3번을 위한 개발이며 5번 구현을 승인한 것이 아니다. 공식 주문 endpoint/DTO를 추측하거나 API 키만으로 live를 켜지 않는다. 일정 때문에 정지·정합성·원가·소유권·손실 한도 검사를 생략하지 않는다. 외부 클라우드 이전은 실거래 전환과 별개이며 로컬 PC 운영 기반을 검토할 수 있다.

다음 실제 실행 여부는 [운영 현황](DEVELOPMENT_STATUS.md)과 저장 증거로 판단한다. 코드/테스트 통과·계획 hash·관측 완료를 실거래 권한으로 사용하지 않는다.
