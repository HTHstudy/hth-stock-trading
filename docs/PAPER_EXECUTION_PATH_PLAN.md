# Paper 체결 경로 검증 계획 — 기존 설정 유지

2026-11-09 작성. 상태는 **설계 완료·미예약·미실행**이다. 이 문서는 Paper 재개 승인이나 실행 입력 manifest가 아니다. 계좌·DB·시세·토큰·worker에 접근하지 않았으며 새 계좌·실행 UUID·코드 복사본·예약을 만들지 않았다. 실제 주문은 계속 비활성이다.

후속 [선행 관측·조기 종료 보강](PAPER_VALIDATION_GUARDS.md)에서 종목·전체 관측 구간·15분 재사용 기한·재개 직전 재검사와 paused/waiting 조기 종료를 구현했다. 아래에서 계획 당시 확인한 공백과 현재 남은 범위를 구분한다. 실제 일정·계좌 준비·Paper 재개는 여전히 수행하지 않았다.

## 목적과 기존 증거

[전략 비교 검토](STRATEGY_COMPARISON_REVIEW.md)는 주전략 채택 근거가 부족하다고 판단했다. 여기서는 수익성 대신 **기존 이동평균 신호 → 리스크 → 주문 의도·예약 → 내부 Paper 체결 → 원장·종료 정리**의 연결을 확인한다. 전략을 잘 고르기 위한 과거 성과 실험과 실제 시세를 사용하는 시스템 경로 검증을 분리한다.

국내·미국의 이전 유한 60 tick은 종료됐지만 의도/체결은 0이다. [미국 결과](US_PAPER_RESULT_2026_11_06.md)의 저장 판단 22건은 HOLD/NO_CROSS였으며 필요 21봉 대비 확정 봉 34~44개를 확보했다. 체결이 없었던 원인을 봉 부족이나 리스크 거부로 바꾸지 않는다. 22건의 저장 진단을 60 tick 전체 판단으로 확대하지 않는다. 기다리는 기존 미국 실행이나 자동 후속 예약은 없다.

## 이번 계획이 검증할 수 있는 범위

**실제 시세 + 모의 체결**이다. Toss에서는 읽기 전용 시세/캘린더만 사용하고 주문 생성·정정·취소·체결 조회 API를 구현하거나 호출하지 않는다. 내부 Paper 체결은 quote·합성 비용·예약 규칙에 따른 결과이며 거래소의 실제 체결·유동성·슬리피지 검증이 아니다.

| 경로                           | 현 설정에서의 가능 범위                            | 완료 판정에 필요한 관측                                                                                           |
| ------------------------------ | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| HOLD·중복 신호 방지            | 가능                                               | 실제 저장 판단과 해당 봉의 의도·예약 보존. HOLD만으로 체결 경로를 완료하지 않음                                   |
| BUY·리스크 거부                | 신호가 발생하면 가능                               | 진단의 BUY/거부 사유와 의도 상태 연결. 한도를 올리지 않음                                                         |
| BUY·예약·1주 체결              | 신호·데이터·리스크가 허용하면 가능                 | 의도 선기록, 다음 tick의 새 quote, 예약·체결·비용·현금·전략 소유권·원가 연결                                      |
| SELL·왕복 대사                 | 같은 실행 창에서 매수 후 매도 교차까지 생기면 가능 | 실제 자기 소유 1주 이내 매도, 해제 원가·실현 손익·잔여 예약·정지 정리                                             |
| 부분 체결                      | **이번 설정에서는 검증 대상 아님**                 | 주문 1주·tick당 최대 체결 1주라 정상 체결은 전량 1주. 부분 체결을 만들려고 수량/한도를 바꾸지 않음                |
| 수동 보유분이 있는 계좌의 보호 | 이번 초기 계좌는 보유 없음                         | 기존 [합성 리허설](PAPER_REHEARSAL.md) 증거를 구분해 유지. 실제 시세에서 보지 않은 보호 경로를 완료 처리하지 않음 |

현재 worker는 `min(잔량, maxFillQuantity)`를 체결 수량으로 사용한다. 부분 체결은 기존 별도 합성 리허설의 2주/1주 조건에서 검증한다. 실제 시세 Paper의 1주 설정에 합성 프레임이나 부분 체결 요청을 주입하지 않는다.

## 고정 설정

[검증 설정 v1](PAPER_VALIDATION_SETTINGS.md)의 값과 파일을 그대로 유지한다. 신규 투자 전략·자금 배분 제안이 아니다. 기본 예제의 KRW 100,000/USD 100 한도와 혼동하지 않는다.

| 항목                      | 국내                                          | 미국                                          |
| ------------------------- | --------------------------------------------- | --------------------------------------------- |
| 입력 계획                 | `examples/paper-market-kr-validation-v1.json` | `examples/paper-market-us-validation-v1.json` |
| 출처·종목                 | toss-readonly · KR:005930                     | toss-readonly · US:AAPL                       |
| 초기 가상 현금            | KRW 1,000,000 / USD 0                         | KRW 0 / USD 1,000                             |
| 전략                      | 이동평균 교차 5/20 · 1.0.0                    | 동일                                          |
| 입력 봉                   | 검증된 종료 1분봉, 최소 21개                  | 동일                                          |
| 주문량 / tick당 최대 체결 | 1주 / 1주                                     | 동일                                          |
| 1회·종목 한도, 비용 포함  | 각각 KRW 200,000                              | 각각 USD 300                                  |
| 일일 손실 차단 한도       | KRW 10,000                                    | USD 10                                        |
| 최대 보유 종목            | 1                                             | 1                                             |
| 합성 매수 / 매도 비용     | 10 / 30 bps                                   | 동일                                          |
| 유한 실행 예산            | 최대 60 tick                                  | 동일                                          |

Paper 비용은 기존 10/30bps 합성 모델이며 별도 슬리피지를 추가하지 않는다. 연구 백테스트의 기본/스트레스 비용·슬리피지를 Paper에 적용하지 않는다.

양 통화 한도는 두 파일 모두 같은 고정값이고 미사용 통화의 현금은 0이다. 환전·통화 합산을 하지 않는다. 비용 포함 한도를 넘는 매수뿐 아니라 가격 상승 후 매도도 거부될 수 있다. 한도를 충족시키려고 자금·가격·수량·전략·계좌를 바꾸지 않는다. 손실 한도는 손절가나 청산 보장이 아니다.

키·DB·시세 없는 기존 계획 미리보기로 두 파일의 strict schema와 정규화 hash를 재확인했다.

| 시장 | planHash                                                           |
| ---- | ------------------------------------------------------------------ |
| KR   | `d950bcc82bc9505e17109125e43ea523664522a4565a751a032899f6dbda2d0c` |
| US   | `adb3fbf91ddf456c09614dd31e31f2ef7ea5a37683c30770f9787d681e634893` |

이는 예제 설정 파일 확인이며 **현재 DB의 잔고·전략 revision·한도·계좌 출처가 일치한다는 확인은 아니다.** 실제 실행을 별도로 요청받으면 서버 manifest와 현재 계좌를 읽기 전용으로 검사해 새 version/epoch·hash 기대값을 고정해야 한다. 과거 준비본/실행의 제어 기대값을 재사용하지 않는다.

## 시작 전에 필요한 입력과 gate

현재 아래 실행별 값은 **미지정·미검증**이다. 빈 값을 임의 기본값으로 채워 실행하지 않는다.

| 필요한 값                                       | 고정할 근거                                                                 |
| ----------------------------------------------- | --------------------------------------------------------------------------- |
| 이번 시장과 서버 고정 계좌                      | 기존 manifest의 시장·toss-readonly 출처, localhost 전용 Paper DB/role       |
| 실제 정규장 시작·종료와 예정 시작·기한          | 새 공식 캘린더 근거, 양 통화 일일 기준 경계, warmup 계획                    |
| 선행 관측 ID·최종 리포트 hash                   | 대상 종목/시장·기간·연속성·오류·공백을 검토한 종료 증거                     |
| 실행 코드/lockfile hash와 고정 코드 root        | 공개 코드·의존성만 분리하고 키·환경·계좌 자료는 복사하지 않음               |
| 고정 계획 resources 경로/hash                   | 별도 절대 경로 pin과 시장·planHash 검증                                     |
| 현재 계좌 version/epoch·전략/한도/manifest hash | 읽기 전용 점검 직후 작성한 기대 제어 값; 기존 파일 덮어쓰기 금지            |
| 실행 의사                                       | 이번 시장·계좌·한도·창·60 tick·중단/정리 범위에 대한 별도 명시적 Paper 재개 |

한 번에 한 시장만 계획·검토한다. KR/US를 병렬 재개하지 않고 같은 client의 기존 DB advisory lock을 사용한다. 다른 소유자의 잠금을 중단하거나 별도 토큰 발급으로 우회하지 않는다. 업무 DB와 전용 Paper DB·토큰 잠금 DB의 역할을 혼동하지 않는다.

과거 a407 요청 누락과 장시간 감독기의 예약 차단은 [예약 감사](PAPER_RESERVATION_AUDIT.md)를 유지한다. 현재 직접 Paper 실행기에 없는 전역 예약 검사를 있다고 주장하거나, 반대로 그 부재를 충돌 없는 실행의 증거로 쓰지 않는다. 새 일정을 잡기 전 현재 예약/소유 프로세스 상태를 별도 검토하고 불확실성이 남으면 예약하지 않는다. 다른 실행의 종료 증거·현재 정지 상태·시간 경과로 과거 기록을 해소하지 않는다.

### 선행 관측과 현 실행기의 검사 범위

계획 당시 runner는 시장·최종 hash·60 healthy와 오류/공백 등을 검사했지만 종목·관측 구간·경과 시간 연결은 빠져 있었다. 후속 보강은 job/report를 고정 종목과 대조하고 전체 표본 범위를 계획 세션에 연결하며 완료 후 15분 이내만 허용한다. 재개 직전에도 재검사한다. 현재 source의 공식 세션 검증을 대신하지 않으며 이전 Paper 60 tick 종료를 선행 시세 관측 60 healthy 증거로 쓰지 않는다.

현재 실제 source의 세션/신선도/봉 검사는 그 후 별도로 수행된다. 과거 리포트나 이 문서의 설정 hash만으로 그 검사를 대신하지 않는다. 보강 코드 검증도 현재 계좌·시장 검사나 자동 실행 준비 완료를 의미하지 않는다.

## 실행 창과 절차

현재 날짜의 구체 시각이나 예약을 만들지 않았다. 공식 캘린더를 다시 조회하지 않았으므로 평일·일반 개장 시각·DST 추정으로 시각을 채우지 않는다. 후속 계획에는 UTC와 KST를 함께 기록한다.

[봉 준비 정책](PAPER_WARMUP.md)에 따라 현재 세션의 첫 완전한 분 구간과 재관측 지연을 반영한다. 기존 5/20의 이론상 최초 시각은 개장 22분 뒤, 기본 여유를 포함한 봉 준비 후보는 25분 뒤다. 이것은 실제 21개 봉 확보 보장이 아니다. 기존 정책으로 검증한 이전 영업일 봉은 그대로 허용하되 생성/시각 변경으로 부족한 봉을 메우지 않는다.

최소 절차 예산은 기존 12분, 기본 창은 25분, 상한은 30분이다. 정규장 종료 전에 정리를 마칠 여유와 **KRW·USD 두 일일 기준 날짜**를 확인하며 자정/미국 거래일 경계를 가로지르는 창은 채택하지 않는다. runner의 실제 재개 단계에는 별도 15분 timeout과 전체 deadline 취소가 있다. tick 완료 후 10초 대기에 I/O 시간이 더해지므로 60 tick을 정확히 10분으로 보장하지 않는다.

1. **무접속 입력 검증:** 실행 의사를 먼저 확인하고 새 resources·code hash·warmup·기대 제어 파일을 준비한다. 이 단계만으로 계좌·시세·재개를 시작하지 않는다. 파일·hash 누락은 DB/대기 전에 차단한다.
2. **계좌 읽기 전용 점검:** 전용 DB/출처·정지·lease 없음·계획/한도/전략/이력/준비 영수증·초기 가상 현금·보유/의도/체결/예약 없음을 확인한다. 현재 runner의 pristine 요구를 우회하지 않는다.
3. **일일 기준 검토:** 필요한 경우 기존 손실 이월 정책으로 별도 검토·적용한다. 이는 DB 변경이므로 현재 문서 작성 단계에서 하지 않는다. 재시작으로 손실을 0으로 만들지 않고 예상 version/epoch 전이를 검사한다.
4. **정지 상태 실제 시세 1회 관측:** 명시적 실행 범위 안에서 기존 source와 잠금을 사용한다. 현재 세션 일치, 새 quote·전체 보유분 mark·`prepareStrategyData`·활성 종목별 21봉을 재검사하고 정지/정리 상태를 확인한다.
5. **실행 직전 checkpoint:** 일일 검토·정지 관측 이후 `before.json`을 새로 캡처한다. 준비 전 checkpoint를 baseline으로 쓰지 않는다. 전략/한도 hash와 최신 제어 CAS가 유지돼야 한다.
6. **별도 명시적 유한 재개:** 새 소유 launch/run으로 최대 60 tick만 실행한다. 새 신호는 의도를 먼저 커밋하고 예약하며 같은 tick에서 체결하지 않는다. 다음 tick의 새 quote와 lease/epoch/잔량/누적 비용으로만 Paper 체결한다.
7. **종료·읽기 전용 대사:** 진행 I/O 정리와 같은 소유자의 잔량 정리/lease 해제 후 `after.json`·review·소유 exit를 보관한다. 진단 capture는 별도 읽기 전용 절차이고 원본 실행 폴더/파일을 변경할 수 있는 허용 범위도 먼저 확인한다. 불가하면 기존 기록을 수정해 끼워 넣지 않고 진단 증거 미확보로 남긴다.

고정 빌드가 실행을 기다리면 workspace의 빌드/커밋 hook으로 그 dist를 덮어쓰지 않는다. 준비·검증을 분리할 때도 같은 code hash와 CAS를 유지하고 키/환경/계좌 자료를 코드 root로 옮기지 않는다.

## 중단 조건과 현재 자동화의 한계

중단은 **신규 의도·예약·체결을 막는 것**과 **프로세스가 종료·정리됐음을 확인하는 것**을 구분한다. 긴급 정지는 DB 정지 기록이며 자동 청산·정리 완료·재개를 뜻하지 않는다.

| 조건                                                            | 거래 측 처리 / 후속 확인                                                                                 |
| --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 시세/API 오류·데이터 지연/불일치·준비 봉 부족                   | 실행 전이면 재개 차단. 실행 중 오류는 기존 worker 실패/정지 경로와 정리를 확인                           |
| 전략/한도/hash 변경·version/epoch CAS 실패·lease/heartbeat 상실 | 새 작업을 승인하지 않고 종료 증거·원장 상태 확인. 기대값을 새로 맞춰 자동 재시도하지 않음                |
| 일일 손실·비용 포함 주문 한도·중복/소유권 제한                  | 위험 주문을 거부하고 사유를 기록. 리스크 거부만으로 즉시 프로세스 전체가 끝난다고 주장하지 않음          |
| 정규장 종료·확인된 휴장·날짜 검토 요구·긴급 정지                | 거래 정지와 예약 정리를 확인. waiting/paused 상태만으로 자식 종료를 추정하지 않음                        |
| deadline·취소·절전/시계 이상·강제 종료                          | 소유 래퍼의 종료/강제 여부와 정리 증거를 확인. 파일 부재/timeout은 미검증으로 남기고 자동 후속 실행 금지 |

후속 보강으로 **재개 구간의 첫 paused/waiting tick에서 기존 정리 경로를 거쳐 조기 종료한다.** 정지 1회 관측의 paused와 running/HOLD, 개별 리스크 거부는 구분한다. tick 반환 전 진행 I/O를 즉시 강제 종료하는 보장은 아니며 기존 긴급 정지·취소·deadline 절차를 유지한다. 담당 소유자는 정리·독립 종료 증거를 확인하고 자신이 시작한 실행만 제어한다.

계획된 한도/기한에 도달하면 신호가 없거나 BUY만 관측했어도 연장·반복·다른 종목 전환을 하지 않는다. 정리 과정은 미체결 잔량/예약만 해제하며 이미 체결한 주식·원가를 되돌리거나 강제 매도하지 않는다.

## 결과 판정과 원장 대사

[기존 대사 verdict](PAPER_RUN_REVIEW.md)를 그대로 유지한다. 아래 경로 판정은 해석용 추가 구분이며 저장된 verdict를 수정하는 새 enum/실행 API가 아니다.

| 실제로 확보한 증거                           | 경로 판단                                                                       |
| -------------------------------------------- | ------------------------------------------------------------------------------- |
| HOLD만 있음·의도/체결 없음                   | 정상 HOLD 관측. 체결 경로는 미검증이고 대사는 incomplete 유지                   |
| BUY/SELL 신호만 있음                         | 신호만 확인. 예약·체결 확인으로 확대하지 않음                                   |
| 리스크 거부 또는 예약 후 미체결·정리         | 실제로 본 거부/예약/잔량 정리만 확인. 체결/비용 경로는 미검증                   |
| 매수 1주 체결, 매도 없음                     | 매수 체결·현금·비용·소유권·원가까지의 일치만 확인. 매도·왕복·부분 체결은 미검증 |
| 같은 창에서 매수 후 자기 소유 매도·대사 일치 | 관측한 왕복 원장 경로만 확인. 수익성·부분 체결·실제 증권사 체결 검증 아님       |
| 손익/원가/중복/소유권/정리 불일치            | issues-found 또는 기존 규칙의 실패. 자료를 고쳐 일치로 만들지 않음              |
| 진단/체크포인트/순서·독립 exit 증거 부족     | 미검증. 종료 코드·60 tick·원장 동일만으로 완료 처리하지 않음                    |

판정 전 다음을 함께 검사한다.

- **연결과 불변성:** 같은 scope/source·before/after·설정 hash·lease 구간·이벤트 집합·요청/종료/launch/exit의 연결. 이전 의도·체결·영구 중복 키·원본 요청은 보존한다. 같은 봉의 두 번째 의도가 있으면 실패다.
- **현금·비용:** 매수는 대금+비용 차감, 매도는 대금−비용 증가. 비용은 원래 costBps와 누적 대금에 대한 통화 최소 단위 올림이며 이미 낸 비용을 이중 부과하지 않는다. KRW/USD를 합산하지 않는다.
- **소유권·원가:** 매수 원가=대금+비용. 매도는 자기 전략 소유량 이내이며 해제 원가와 실현 손익=매도 대금−비용−해제 원가를 대조한다. 남은 원가는 마지막 잔량까지 보존한다.
- **종료 상태:** stopped, lease 없음, 활성 예약 없음, INTENT_RECORDED/READY/PARTIALLY_FILLED 진행 의도 없음. 종료 보유 수량이 있어도 강제 청산하지 않는다.
- **해석:** 일일 손익에는 평가 변화가 포함되므로 실현 손익 합계와 같다고 요구하지 않는다. 진단은 30초 저장 억제가 있어 기록 수와 tick 수를 같게 놓지 않는다. 평가자산 변화를 전략 수익률로 바꾸지 않는다.

## 매수 후 다음 실행에 대한 제약

현 `authorized-paper-validation.mjs`는 매 실행마다 초기 가상 현금·보유/의도/체결/예약 없음 등을 요구한다. 이번 창에서 매수만 체결되면 기존 계좌는 더 이상 그 조건을 충족하지 않으므로 **다음 창에 같은 pristine 실행기를 반복해 매도를 기다릴 수 없다.** 불일치 시 PAPER_ACCOUNT_NOT_PRISTINE을 유지한다.

매수 체결뿐 아니라 의도만 기록돼도 noOrders 조건을 충족하지 못하므로 후속 실행이 차단될 수 있다. 전량 매도해 현금/보유가 돌아와도 이력은 남으므로 pristine으로 복원되지 않는다.

현금 재설정·보유 삭제·주문 이력 제거·새 계좌 생성으로 제약을 우회하지 않는다. 매수된 주식과 원가를 정지 상태로 보존하고 결과를 검토한다. 후속 실행이 필요하면 기존 잔고·이력·일일 손실·소유권을 인정하는 별도 실행 전 조건과 CAS/대사 기준을 설계·구현하는 작업이 먼저다. 이번에는 그 지원을 구현하거나 기존 실행기의 pristine gate를 완화하지 않았다.

## 완료한 준비와 남은 실행 준비

완료한 것은 설정 파일 strict 미리보기/hash 확인, 기존 코드/증거의 적용 범위 검토, gate·중단·경로별 대사 기준 고정이다. 현재 DB/시장 검사, 특정 일정, resources/control/build pin, 선행 관측 채택, 실행 승인, 소유 프로세스 생성은 하지 않았다.

남은 작업은 다음과 같이 분리한다.

1. **지금 개발 가능한 것:** 의도·체결 이력이 있는 계좌의 후속 검증 설계. 선행 관측 연결과 paused/waiting 조기 종료는 후속 보강에서 구현했으며 실제 시장 검증과 구분한다. 기존 CAS·한도·정지·자료 보존은 유지한다.
2. **실행 시에만 확인 가능한 것:** 최신 공식 세션, 계좌 출처/제어/리스크와 새 시세·실제 확정 봉·신호. 지금 확인한 설정 hash를 해당 검사 완료로 대신하지 않는다.
3. **별도 실행 의사가 필요한 것:** 해당 시장의 유한 실제 시세 Paper 재개. 부분 체결/수익성을 보장하지 않으며 기존 미래 연구 계획과 장시간 감독기 차단도 그대로다.

## 검토·검증 범위

설정의 두 strict 미리보기는 `TRADING_MODE=paper`로 기존 컴파일 CLI만 직접 호출해 수행했고 .env 자동 로딩·빌드·DB·broker 생성 없이 preview와 기존 planHash 일치를 확인했다. 이는 실행기 자체의 검증이나 최신 계좌 준비 확인이 아니다. 문서만 변경하며 새 런타임 코드·의존성·마이그레이션은 없다.

구현 경계는 [유한 실행기](../infra/authorized-paper-validation.mjs)의 선행 관측/초기 계좌 gate·onTick·종료 판정과 [worker](../apps/worker/src/paper-worker.ts)의 체결량·신호/의도 순서·run loop를 읽어 확인했다. 독립 읽기 전용 검토에서도 부분 체결 불가·의도 기록 후 pristine 재실행 불가·paused/waiting과 종료의 차이·a407 차단 적용 범위를 확인했다. 현재 계좌나 실행 중인 프로세스의 상태를 점검한 결과는 아니다.

문서 포맷·링크와 설정/계획 hash를 확인하며 앱 전체 테스트나 DB 통합을 다시 실행하지 않는다. 기존 검사 통과를 이번 실제 시장/계좌 검증 통과로 표시하지 않는다.
