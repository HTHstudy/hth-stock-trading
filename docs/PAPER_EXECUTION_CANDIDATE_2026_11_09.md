# 미국 우선 유한 Paper 실행 후보 — 2026-11-09

상태는 **후보 계산 완료·예약 보류·미실행**이다. [계산 자료](PAPER_EXECUTION_CANDIDATE_2026_11_09.json)는 사람의 검토를 위한 문서이며 runner가 받는 실행 manifest가 아니다. 키·환경파일·DB·broker·시세·worker를 열지 않고 기존 예제 계획과 순수 시간 계획 함수로 계산했다. 후보 시각이 와도 자동으로 실행하지 않는다.

## 대상과 현재 근거

[15:49 읽기 전용 점검](PAPER_CONTINUATION_REVIEW_2026_11_09.md)에서 KR/US 기존 계좌는 모두 기본 runner의 초기 모드 12조건을 충족했다. 미국은 이전 종료 원장과 현재 원장도 일치했다. 이번에는 독립 종료 증거와 계획 연결이 있는 **미국 AAPL 한 시장만 먼저** 검토한다. 국내는 미국 결과 검토 후 별도 계획하며 동시에 재개하지 않는다. 수익성이나 종목 추천에 따른 순서가 아니다.

주문·체결 이력이 0인 현재 후보는 기존 계좌의 기본 pristine 모드를 우선한다. 당시 상태가 실제 실행 때도 유지되는지 다시 검사해야 한다. 이력이 생겼다면 초기화/삭제로 되돌리지 않고 [continuation 부모·현재 원장 검사](PAPER_CONTINUATION.md)를 별도로 통과해야 한다. 국내의 누락된 과거 증거를 미국 것으로 채우지 않는다.

MA 5/20·1.0.0, 1주/최대 체결 1주, 기존 KRW/USD 현금·한도·10/30bps 비용·최대 60 tick은 [원래 계획](PAPER_EXECUTION_PATH_PLAN.md) 그대로다. 두 예제 planHash를 다시 검증했고 설정 파일은 수정하지 않았다. 실주문은 계속 비활성이다.

관측은 같은 종목 US:AAPL·새 60개 healthy·오류/closed/blocked/시세 역행/공백 0·최종 journal hash 검증을 요구한다. 기존 11/5 리포트나 이전 Paper 60 tick을 재사용하지 않는다. 실제 관측 job/report ID·hash·종료 F는 아직 없으며 JSON에서도 null이다.

## 일일 검토와 실행 절차

1. **현재 예약/소유 증거부터 검토한다.** 아래 미해결 사항이 남은 상태에서는 이 후보의 관측·재개를 예약하지 않는다. 다른 CLI·새 데이터 루트·새 DB로 우회하지 않는다.
2. 해당 시장·기존 계좌·유한 창에 대한 별도 실행 의사, 최신 토스 캘린더·정규장, 새로운 코드/lockfile·resources·서버 제어 기대값을 확인한다. 개발 중인 dist를 기다리는 프로세스에 연결하지 않는다.
3. 승인된 새 관측만 수행하고 정상 정리·최종 리포트를 확인한다. HTTP 조회나 문서 읽기가 자식을 시작하지 않는다. 실패/기한 초과/불확실한 종료는 자동 재시도하지 않는다.
4. 관측 종료 F가 생긴 뒤 새 Paper 시각과 warmup·KRW/USD 양쪽 날짜 경계를 확인한다. 현재 계좌의 source·정지·lease·설정·현금/보유/이력 또는 continuation baseline을 다시 검사한다.
5. runner의 실제 시작 시점에 `planPaperDayReview`를 새로 계산한다. 계획은 5분 만료이며 15:49의 날짜 검토 필요 결과나 미리 만든 plan을 밤까지 보관해 적용하지 않는다. carry-negative-pnl-v1·expectedVersion·lease/epoch·대상 날짜와 신선한 전체 보유분 평가를 함께 확인해 별도 적용한다. 날짜/손실을 직접 수정하지 않는다.
6. 정지 상태 시세 1회 관측 후 실제 세션·quote·전체 보유분·`prepareStrategyData`·21개 확정봉·최신 제어를 검사한다. 설정이 달라졌다면 기대값을 맞춰 재시도하지 않는다.
7. 새 before checkpoint와 재개 직전 선행 리포트 hash/15분 기한을 확인하고, 명시적 실행에만 최대 60 tick을 수행한다. 첫 paused/waiting은 기존 정리 뒤 조기 종료하며 deadline·취소·lease 상실도 구분한다.
8. after·대사·구간 진단과 직접 소유 launch/exit를 연결한다. 의도/체결 0이면 미검증을 유지하고 신호를 만들기 위해 전략·한도·창을 변경/연장하지 않는다. 매수만 체결됐다면 보유분/원가를 정지 상태로 보존한다.

현재 미국 계좌의 저장 날짜는 KRW 11/6·USD 11/5다. 위 실제 실행 후보의 날짜는 KRW 11/10·USD 11/9이므로 기존 11/9 오후 점검의 목표 날짜를 그대로 적용해서는 안 된다. 실제 DB 시각의 새 계획을 사용해야 한다. 국내 날짜 검토도 별개이며 미국 실행으로 국내 계좌를 변경하지 않는다.

## 계획 당시 실행 연결에서 필요했던 개발

계획 작성 당시 `market:observe --regular-only`는 표본 수·프레임 timeout·시작 지연을 검사하지만 절대 종료 기한 인자는 받지 않는다. `readonly:supervise`의 계획 종류는 session/expiry로 제한돼 있다. 장중 60표본 관측을 세션 전환이나 토큰 만료 검증으로 표시하거나 존재하지 않는 `--deadline`을 market:observe에 전달하지 않는다.

따라서 이 후보의 **일반 정규장 60표본용 유한 감독 연결은 아직 구현하지 않았다.** 실제 실행 전에는 일반 관측용 계획/자식 감독·정리 기한과 최종 관측 job/report 연결을 구현·검증해야 한다. 기존 예약 감사·고정 빌드·단일 소유 자식·정상/강제 종료 구분을 그대로 재사용하는 범위가 다음 개발 작업이다. 가짜 자식/시계와 합성 자료로 개발할 수 있으므로 실제 시장이나 예약 차단 해제를 기다릴 필요가 없다.

후속 [일반 정규장 감독·최종 증거 연결](REGULAR_OBSERVATION_SUPERVISION.md)에서 이 개발을 구현했다. 원래 JSON 후보의 입력/hash와 당시 미구현 기록은 보존한다. 실제 관측·예약·재개와 아래 미해결 예약 처리는 수행하지 않았다.

## 지금 보류된 이유

기존 a407 기록에는 [독립 소유 종료 증거](PAPER_RESERVATION_AUDIT.md)가 없다. 마지막 읽기 전용 감사는 unresolvedCount=1이었고, 실제 시장 `readonly:supervise`는 이 경우 자식 생성 전에 `SUPERVISOR_RESERVATIONS_UNVERIFIED`로 차단한다. 이 후보는 그 제약을 유지한다. 현재 직접 Paper runner에 같은 전역 예약 검사가 없다는 사실을 우회 경로로 사용하지 않는다.

이는 새 미국 결과나 다음 개장을 기다리면 사라지는 문제는 아니다. 당시 run과 연결되는 실제 독립 자료 확보 또는 별도 처리 정책 설계·검토가 필요하다. 과거 원본 수정·소급 launch/exit·다른 run 증거 재사용·근거 없는 수동 예외는 허용하지 않는다. 이번 작업에서는 정책 변경·예외·예약 정리를 하지 않았다.

따라서 후보 JSON의 state는 draft-blocked-not-scheduled, buildHash/resourcesDirectory/expectedControlHash/실제 관측 식별자는 null이다. 아직 실행 manifest를 발급하지 않았고 코드 복사본이나 private 실행 UUID도 만들지 않았다. 후보 기한이 지나면 다음 날로 이월하지 않고 그 후보를 만료된 검토 자료로 남긴다.

## 검증 범위

두 예제 planHash·두 시간 시나리오의 warmup hash와 양 통화 날짜·기존 15분 상수를 확인했다. 너무 이른 시작·자정 횡단·세션 종료 초과의 세 입력은 기존 함수가 거부했다. 계산 문서 JSON의 hash를 저장 후 재검증하고 링크·포맷도 검사한다. 새 의존성·소스·스키마 변경이 없어 전체/DB 통합 테스트를 다시 실행하지 않는다. 실제 캘린더·시세·계좌·재개 검증 완료나 자동 운용 승인은 아니다.
