# 미국 Paper warm-up 수집 점검

## 조사 범위와 결론

2026-11-04 23:35 KST 실행의 보존된 `preflight-evidence.json`만 읽었다. 해당 기록은 정규장 `open`, 시장 데이터 `ready=true`, 차단 사유 없음, 확정봉 4개, 정지·정리 완료를 보고한다. 계좌 파일·시세 원본·실제 API는 조회하지 않았다. 원본 증거를 수정하지 않았다.

**개장 후 5분과 확정 지연 60초로 당일 확정봉 4개를 재현했다. 조사한 코드와 가짜 broker 테스트에서 collector의 임의 잘림·페이지 처리 오류는 발견하지 않았다.** 다만 보존된 증거에는 당시 원본 봉·페이지 응답·cursor가 없으므로, 실제 응답이 당일 봉만 포함했는지 또는 이전 거래일 페이지가 있었는지는 증명할 수 없다. 수집 버그가 없다는 전체 API 보장은 아니다.

읽은 구현은 `paper-market-source.ts`, `collect-candles.ts`, broker의 기존 `getCandles`, `prepareStrategyData` 및 봉 확정 정책이다. [시장 데이터 정책](MARKET_DATA_POLICY.md)과 [기존 명세 확인 기록](TOSS_API.md)을 기준으로 점검했다. 공식 명세를 새로 조회하거나 endpoint·DTO·collector 소스를 변경하지 않았다.

## 5분과 25분 재현

합성 fixture는 미국 종목 하나, 2026-11-04 정규장 시작 `14:30:00Z`(23:30 KST), 종료 `21:00:00Z`, 해당 세션의 1분봉을 사용한다. 날짜·가격·캘린더는 테스트 입력이며 실제 시세 기록이나 새 공식 일정 확인이 아니다. 봉 timestamp는 구간 종료 시각이며 첫 봉은 `14:31:00Z`다.

| 관측 시점  | 응답 봉 수 | 확정봉 수 | 마지막 봉           | slow=20 전략    |
| ---------- | ---------: | --------: | ------------------- | --------------- |
| 개장 +5분  |          5 |         4 | 종료 후 60초 미경과 | HOLD / WARMUP   |
| 개장 +21분 |         21 |        20 | 종료 후 60초 미경과 | HOLD / WARMUP   |
| 개장 +22분 |         22 |        21 | 종료 후 60초 미경과 | HOLD / NO_CROSS |
| 개장 +25분 |         25 |        24 | 종료 후 60초 미경과 | HOLD / NO_CROSS |

이동평균 교차에는 직전·현재 평균 비교 때문에 `slowPeriod + 1 = 21`개의 확정봉이 필요하다. 매 분 데이터가 빠짐없이 제공된다는 fixture 조건에서 최소 시점은 개장 +22분이다. +25분은 계획 여유로 사용할 수 있지만 실행 보장은 아니다. 네 분이 누락된 별도 +25분 fixture는 여전히 확정봉 20개이며 WARMUP이다. 실제 실행 전 재수집·신선도·확정봉 수 검사를 유지해야 한다.

일찍 수집한 마지막 봉은 60초 뒤 시계만 진행시켜도 확정되지 않는다. `BAR_NOT_REOBSERVED`로 남고 새 source 수집 후에만 확정된다. 시장 데이터 `ready=true`와 전략 warm-up 충족은 별도 조건이다. 상수 합성 가격의 `NO_CROSS`는 주문·체결·수익성 검증이 아니다.

## 수집과 페이지 경계

- source 기본값은 종목당 `maxPages=1`; collector는 `interval=1m`, `count=200`, `adjusted=false`로 요청한다. 21개는 페이지 요청 개수가 아니라 전략에 필요한 **확정봉 수**다.
- collector는 반환된 봉을 시간순으로 정렬하고 timestamp 중복을 제거한다. 모든 결과의 `isClosed`를 false로 재설정한다. source도 이를 확정하지 않는다. 준비 검사는 별도 복사본에서 확정하며 원본을 바꾸지 않는다.
- 5개·25개를 반환하고 `nextBefore=null`인 fixture는 한 번 요청하고 모두 보존한다. source가 4개로 잘라내는 동작은 없다. 5개 중 4개가 되는 시점은 확정 정책 평가다.
- `nextBefore`가 있더라도 페이지 상한 1이면 추가 요청하지 않는다. 상한 2에서는 응답 cursor를 `before`로 전달하며 inclusive 경계 중복을 제거하고 25개를 보존한다. 최신 요청의 경계 값을 유지한다.
- 빈 종단 페이지에서는 중단하고, 반복 cursor는 실패한다. 누락 분을 합성하거나 자동으로 페이지 상한을 늘리지 않는다.

collector는 현재 세션만 추려 반환하는 모듈이 아니다. 준비 검사는 제공된 캘린더에서 이전 영업일 봉도 평가할 수 있다. 이번 fixture는 현재 정규장 봉만 제공해 그 구간의 필요 시간을 검증한 것이며, 모든 실응답이 현재 세션에 한정된다고 단정하지 않는다. 이전 거래일 데이터를 warm-up에 허용할지는 main의 계획기·runner 정책에서 명시해야 한다. 시간외 봉을 정규장 봉으로 간주하거나 오래된 저장 플래그로 확정을 대체하지 않는다.

## 검증과 후속 연결

가짜 broker/fetch만 사용하는 두 테스트 파일을 직접 Vitest로 실행한다. dist 빌드·DB·계좌·실제 시세·토큰·주문·예약은 사용하지 않는다.

```sh
corepack pnpm exec vitest run apps/worker/src/paper-market-source.test.ts apps/worker/src/collect-candles.test.ts
```

main은 개장 시각·봉 주기·확정 지연·필요 봉 수를 계획에 반영하고, 실제 준비 검사에서 부족하면 재개를 차단하는 정책을 유지한다. 이 테스트 결과로 과거 실패를 성공으로 바꾸거나 자동 재시도·실행 예약·거래 권한을 만들지 않는다.

이번 검증은 두 파일의 24개 테스트, `tsc -p tsconfig.tools.json --noEmit`, 지정 파일 ESLint·Prettier와 diff 검사가 통과했다. 통합 빌드·DB 통합 테스트는 실행하지 않았다. 지정 테스트 두 파일과 이 문서만 수정했으며 커밋·푸시는 하지 않았다.
