# Paper 내부 합성 체결

## 범위

`createDatabase(url).paper.fill(accountId, intentId, leaseToken, { fillId, quantity }, evidence)`는 **내부 DB 모의 체결**이다. 증권사·네트워크·실제 계좌와 연결하지 않는다. 기본 정지·Paper 모드를 유지하며 `executionEnabled=false`다. [Paper worker](PAPER_WORKER.md)가 순차 tick과 복구·관측 갱신을 조립하며 CLI는 합성 테스트 DB 전용이다. [로컬 합성 Paper 조회·정지 API/화면](PAPER_DASHBOARD.md)을 추가했다. 실제 시세에는 연결하지 않았다. 의도 선기록과 예약은 [Paper 원장](PAPER_LEDGER.md)을 따른다.

`quote-proxy-v1`은 주문 예약 후 새로 관측한 현재가를 체결가의 대용으로 사용하는 제한된 검증 모델이다. 매수는 KRW 1원/USD 1센트 단위로 올림하고 매도는 내린다. 매수 가격 ≤ 지정가, 매도 가격 ≥ 지정가일 때만 체결한다. 호가·거래량·대기열·시장별 tick·정산일·실제 세금 체계를 재현하지 않는다. 슬리피지는 별도로 넣지 않으며 현재가와 비용 가정만 사용한다. 부분 체결 수량은 신뢰된 서버 호출자가 명시한다. 실제 체결 확률이나 투자 성과의 근거로 사용하지 않는다.

## 실행과 중복 방지

1. 계좌 행 잠금을 얻고 `(accountId, fillId)`를 먼저 조회한다. 같은 intent·수량·모델의 이미 커밋된 체결은 원본 그대로 반환한다. 정지·lease 만료 후에도 재조회할 수 있으며 새 시세로 재계산하지 않는다. 같은 키의 다른 요청은 충돌 이력을 남기고 거부한다.
2. 새 체결은 READY/PARTIALLY_FILLED, 현재 lease, 정지 해제, 동일 epoch·전략 버전/활성, 원래 예약 유효시간을 요구한다. lease 갱신은 예약 기한을 연장하지 않는다.
3. quote의 원천/관측 시각은 예약 decision.checkedAt 이상이어야 한다. 종목·데이터 신선도·수집 상태·미확인 주문·정규 세션·환율·캔들/캘린더를 다시 검사한다. 요청 통화의 모든 보유분 mark도 신선해야 한다. resting 주문의 원래 신호가 계속 최신 봉일 필요는 없다.
4. 지정가 미도달은 `fill=null`이며 자금·수량을 변경하지 않는다. fillId도 소비하지 않는다. 다른 거부는 안전한 오류 코드와 감사 이력을 남긴다.
5. 순수 `settlePaperFill` 계산 후 체결 행·전략 원가·의도 누적 합계와 상태·잔여 예약·계좌 ledger/version·감사 이력을 한 트랜잭션에 저장한다. 마지막에 DB 시각으로 lease·예약·데이터 만료를 다시 검사한다. 실패하면 이번 체결 전체가 롤백된다.

이미 커밋된 체결을 불확실한 응답 때문에 새 키로 재생성하지 않는다. `readFills`나 동일 fillId 요청으로 확인한다. `readFills`는 내부 저장 데이터이며 공개 API/로그로 원본을 노출하지 않는다. DB 장애로 트랜잭션 자체가 실패하면 실패 이력도 저장되지 않을 수 있다. 먼저 커밋된 의도·예약·기존 체결은 복구 근거로 남는다.

## 비용·잔여 예약

금액 계산은 decimal.js 100자리 정밀도와 십진 문자열을 사용한다. 외부 라이브러리는 추가하지 않았다. 수수료·세금 추정은 예약 시 고정한 방향별 costBps 한 값이며 실제 증권사 청구를 의미하지 않는다.

```text
누적 비용 = ceil(누적 체결대금 × costBps / 10000 / 통화 최소단위) × 최소단위
이번 비용 = 새 누적 비용 − 이미 지불한 비용
매수 잔여 예약 = 잔량 × 예약 평가단가
               + fee(누적 체결대금 + 잔량 × 예약 평가단가) − 이미 지불한 비용
```

부분 체결 횟수마다 수수료를 새로 올림하지 않는다. 예를 들어 USD 0.01짜리 2주, 10bps의 주문은 총 수수료가 USD 0.01이다. 1주 체결 후 남은 예약은 USD 0.01이며 수수료를 다시 예약하지 않는다. 리스크 snapshot에도 filledNotional/paidCosts를 전달하고 같은 공식을 사용한다. 매수 대금+비용+잔여 예약은 기존 자기 예약 이내여야 하고, 체결 후 현금은 타 주문 예약까지 충당해야 한다.

## 소유권·원가·손익

- 매수는 해당 전략 소유 수량과 비용 포함 원가를 증가시킨다. 기존 수동 보유분을 편입하지 않는다. Paper 안에서는 체결분을 즉시 매도 가능으로 간주한다. 실제 결제·주문 가능 현금 모델과 다르다.
- 매도는 해당 전략 소유 수량과 전체 매도 가능량에서 타 예약을 보존한 범위만 허용한다. 원가 기록과 소유 수량이 다르면 거부한다. 과거 테스트에서 직접 주입한 자동 보유분도 원가 없이 체결할 수 없다.
- 평균 원가를 비례 해제하되 통화 최소단위 아래는 내림하고, 마지막 전략 소유분 매도 시 남은 원가 전액을 해제한다. 실현 손익은 매도대금−이번 비용−해제 원가다. 수동/타 전략 원가는 사용하지 않는다.
- 일일 순손익은 기존 값에 `체결 후 해당 통화 평가자산−체결 전 평가자산`을 더한다. 이미 평가한 이익을 실현 손익으로 다시 더하지 않는다. 해당 종목 mark는 체결 가격으로 갱신하고 다른 mark는 보존한다. 일일 손익 날짜와 기존/예상 손실·남은 예약 비용을 검사하고 한도 도달 시 새 체결을 차단한다. 자동 청산은 하지 않는다.
- 부분 체결 후 abort/정지/worker 교체는 이미 보유한 주식과 원가를 되돌리지 않는다. 잔량만 중단한 뒤 기존 복구 절차를 수행한다.

모든 보유분 평가·일일 손익과 연속 관측 중 거래일 전환은 worker의 observe 경로에 추가했다. 장시간 중단 뒤 거래일 전환은 확인을 요구하며 실제 broker의 일일 기준과 다를 수 있다. 현재 reconcile은 신뢰된 서버가 검토한 mark/일일 손익으로 복구하는 메서드다. 체결로 observedAt을 갱신해도 각 mark의 원천/관측 시각 검사는 유지한다.

## DB 보호와 검증

`0003_silent_harpoon.sql`은 paper_fills, paper_cost_basis, 의도 누적 수량/대금/비용과 부분/전체 체결 상태를 추가한다. 기존 enum 컬럼은 CHECK가 있는 text로 바꾸어 새 enum 값을 같은 마이그레이션 트랜잭션에서 사용하는 PostgreSQL 제약을 피한다. 기존 enum 타입은 호환성을 위해 남긴다. 자동 실행·사용자 DB 적용은 하지 않았다.

SQL 트리거는 체결의 변경/삭제/truncate, 지정가·비용 불일치, 부당한 상태 전이·예약 변경을 차단한다. 지연 제약은 커밋 시 누적 합계와 체결 행의 합, 상태와 활성 예약·잔량의 일치를 요구한다. SQL 비용 계산은 정수 몫/나머지로 올림한다. ledger와 원가의 원자성은 계좌 잠금을 공유하는 repository 트랜잭션이 담당한다. DB 관리자나 우회 SQL까지 완전한 회계 검증을 제공하지 않는다.

검증은 localhost의 hth_test/hth_readonly_test 전용 임시 DB와 합성 시장 증거만 사용한다. KRW/USD 비용·동시 체결·동일 키 재조회·잔량 초과·수동 보유 보호·중단·장애 rollback·처리 중 lease 만료·새 worker 인수·불변 이력과 DB 합계 제약을 검사한다. 기존 시장 데이터/백테스트/리스크 테스트도 함께 실행한다. 테스트는 실제 증권사 API를 호출하지 않는다.

## 다음 구현

1. 상시 Paper worker의 단일 소유권·lease 갱신·중단·재시작 복구 루프는 합성 데이터로 구현·검증했다.
2. 예약을 유지하는 관측 갱신, 연속 관측 중 거래일 전환, 만료 잔량 처리를 추가했다. 실제 시세 source와 실제 운영 세션/일일 기준을 검증한다.
3. 신뢰된 전략 신호 → 의도 선기록 → 예약 → 모의 체결을 합성 입력으로 통합 검증했다. 사용자 DB의 초기 자금·한도와 마이그레이션 적용은 별도 검토한다.
4. Paper 전용 상태·거래/실패 이력·긴급 정지 UI를 합성 테스트 DB로 연결했다. 소유자 인증과 전략 관리·실제 시세 검증을 진행한다. 실제 broker 주문·체결 대사는 별도 단계다.
