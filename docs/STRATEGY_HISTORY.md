# Paper 전략 변경 이력

## 화면과 범위

Paper 화면의 등록 전략에서 **변경 이력**을 누른다. 리비전·저장 시각(한국)·변경 주체·등록 활성·구현 버전을 최신순으로 최대 20개씩 표시한다. 리비전을 선택하면 종목·이동평균 기간·주문 수량·관측당 최대 체결 수량·활성·구현 버전을 현재 설정과 비교하고 차이를 강조한다.

각 페이지의 현재 설정과 과거 이력은 같은 DB snapshot에서 읽는다. 페이지 이동이나 다시 읽기 사이에는 현재 설정이 바뀔 수 있다. 비교 표의 현재 리비전을 기준으로 확인한다. 정의가 없는 과거 값은 ‘미등록’으로 표시하며 기본값을 추정하지 않는다. revision=0이고 이력이 없는 기존 전략은 빈 목록이다.

조회는 설정 저장·복원·worker 시작·거래 재개를 수행하지 않는다. 등록 활성은 실행 상태가 아니다. 출처 미확인 계좌도 조회는 허용하지만 편집 제한은 유지한다. 복원 기능은 아직 제공하지 않는다.

## API와 정합성

`GET /v1/paper/strategies/:id/history`는 소유자 인증·localhost·Paper 기능 활성화를 요구한다. 계좌는 서버 설정으로 고정한다. 선택 쿼리는 양의 정수 `beforeRevision` 하나이며 해당 리비전 미만을 조회한다. `nextBeforeRevision`이 null이면 마지막 구간이다. 임의 계좌·페이지 크기·파일 경로를 받지 않는다.

읽기 전용 repeatable-read 트랜잭션과 기존 3초 statement timeout을 사용하며 계좌 행을 잠그지 않는다. 현재 전략과 최신 이력의 연결, 반환 구간과 다음 페이지 경계 행의 내용 hash·리비전 연속성을 검사한다. 누락·불일치 시 결과를 제공하지 않는다. 과거 전체를 매번 스캔하지 않으며 내용 hash는 변경 주체의 암호학적 서명이 아니다.

응답에는 표시용 전략 조건과 이력만 포함한다. 계좌 ID·내부 hash·lease token·감사 원문은 제외한다. 없는 전략은 404, 입력 오류는 400, 저장소·출처·무결성 오류는 상세 원문 없이 503이다. 인증/비활성 차단은 기존 정책을 따른다. 화면은 조회 실패 시 이전 비교 결과를 정상 결과로 표시하지 않는다.

## 구현과 검증

기존 `paper_strategy_revisions`와 공통 계약·TanStack Query를 재사용한다. 새 의존성·서비스·마이그레이션은 없다. 저장 정책은 [전략 설정](STRATEGY_SETTINGS.md)을 따른다.

격리된 테스트 DB에서 25개 리비전의 페이지 경계, 계좌 분리, 계좌 행 잠금 중 조회, 조회 전후 원장/제어 상태 보존, 내용 hash 불일치 차단을 검증한다. API는 인증·출처·입력·비공개 필드 차단을 확인하고, 화면 비교는 미등록 값 보존과 변경 필드 구분을 검증한다. 실제 증권사 API와 주문은 테스트에 사용하지 않는다.
