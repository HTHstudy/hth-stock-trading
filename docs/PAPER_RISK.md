# Paper 리스크 검증 기반

## 구현 범위

`evaluatePaperRisk`는 명시적으로 전달한 검사 시각·Paper 주문 후보·한도·정지 상태·계좌 원장 snapshot·시장 데이터에서 예약 가능 여부를 계산한다. 순수 함수이며 broker·DB·현재 시스템 시각·로그에 의존하지 않는다. 외부 입력은 Zod로 검증하고 실패 시 `canReserve=false`를 반환한다. 결과의 `executionEnabled`는 항상 false다.

이 결과는 **DB 예약이나 주문 실행 승인 자체가 아니다.** 이후 [Paper 원장](PAPER_LEDGER.md)에 연결해 잠금 안의 재평가·동시 예약·영구 dedupe·정지/lease·복구 조건을 구현했다. 내부 합성 체결도 구현했으며 [체결 모델](PAPER_FILLS.md)을 따른다. 상시 Paper 실행기는 합성 데이터로 연결했다. [로컬 합성 Paper 조회·긴급 정지](PAPER_DASHBOARD.md)도 추가했다. 실제 계좌·실제 시세 source·HTTP 실행/재개는 후속이다. 기존 백테스트 체결 엔진에도 이 검사를 자동 적용하지 않았으므로 이전 리포트가 새 정책을 통과했다고 주장하지 않는다.

## 계좌·소유권·통화 계약

- 주문 후보는 paper·한 계좌·한 전략·한 종목의 지정가/정수 수량으로 제한한다. 실제 broker DTO나 실제 주문 API가 아니다.
- snapshot의 현금은 예약 차감 전의 결제 완료 현금이다. 예약은 활성 상태의 **미체결 잔량**만 입력한다. 부분 체결 후에는 체결분을 현금·소유 수량에 반영하고 남은 예약만 유지해야 한다.
- 종목 수량은 수동 수량 + 전략별 자동 소유 수량의 합과 정확히 같아야 한다. 종목·전략 소유권·예약 ID 중복, 수량 부족, 과다 예약은 전체 검사를 차단한다.
- sellableQuantity는 Paper의 내부 예약을 차감하기 전 매도 가능 수량이다. 실제 증권사 필드가 이미 주문 예약을 차감했다면 그대로 대입하지 않는다. 실제 정산/소수점 주문 지원은 후속이다.
- 매도 수량은 `min(자기 소유 수량-자기 매도 예약, 전체 매도 가능 수량-모든 전략의 매도 예약)` 이내여야 한다. 다른 전략과 수동 보유 수량은 가져다 쓰지 않는다. 매도 예정 대금도 체결 전에는 현금으로 쓰지 않는다.
- KRW와 USD를 별도로 계산하고 자동환전·통화 간 대체를 하지 않는다. 계좌의 모든 실제 보유 종목과 매수 예약을 최대 보유 종목 수에 포함한다. 수동 보유분도 포함하는 보수적인 기본값이다.

신규 매수는 해당 계좌에 종목을 이미 보유하거나 같은 종목의 매수 예약이 있으면 차단한다. 수동 보유 종목에 별도의 자동매매 물량을 추가하는 것도 현재는 허용하지 않는다. 반대 방향의 활성 예약은 양 시장 모두 충돌로 차단한다. 매도 예약 중 추가 매도는 미예약 자기 수량 범위에서만 허용한다.

## 검사 순서와 금액

1. control·limits·snapshot 존재, Paper 모드, 정지 상태, 계좌 일치, worker 소유권·전략 활성·수집 정상·미확인 주문·dedupe 상태를 확인한다.
2. 기존 `prepareStrategyData`로 quote 원천/관측 시각, 계좌·캘린더·캔들·환율, 종목 제한과 정규 세션을 다시 검사한다. 과거 dataQuality 보고서의 ready 값을 받지 않는다.
3. 소유권과 예약 원장의 합계·고유성·매도 가능량·현금 정합성을 검사한다. 요청 통화의 모든 보유분 mark에는 원천 시각과 관측 시각을 요구한다. 외화 보유분을 종목 수로 셀 때 외화 가격을 요청 통화로 합산하지 않는다.
4. 시장 거래일의 순손익과 남은 예약 비용·신규 비용을 합쳐 일일 손실 한도를 검사한다. 한도에 도달하면 매수·매도 모두 차단하며 자동 청산하지 않는다. 순손익은 수동 보유분까지 포함한 해당 계좌·통화의 실현/미실현 손익·이미 발생한 비용을 반영한 값으로 미래 원장 계층이 계산해야 한다. 이 함수는 cost basis에서 손익을 재구성하지 않는다.
5. 1회 금액·종목별 금액·최대 보유 종목 수·가용 현금·자기 매도 수량을 확인한다. 중복 의도는 `dedupeClear=false` 또는 같은 ID의 활성 예약으로 차단한다. 영구 중복 검사는 아직 DB에 구현하지 않았다.

금액은 기존 decimal.js의 독립 정밀도 100자리 clone으로 계산한다. 신규 평가 단가는 `max(지정가, 최신 quote)`이며, 수량을 곱한 금액에 명시적인 방향별 costBps를 적용한다. 비용은 KRW 1원·USD 0.01 단위로 올림한다. buyCostBps/sellCostBps는 합성 Paper의 합산 비용 가정이며 실제 증권사 수수료·세율이 아니다. 한도와 결제 현금은 통화 최소 단위의 배수여야 한다.

1회 한도는 비용을 포함한다. 종목별 한도는 기존 전체 보유분 평가 + 같은 종목의 미체결 매수 잔량 평가/비용 + 신규 평가/비용을 포함한다. 새 매수 예약 현금에는 비용까지 포함하고, 매도 예약은 자기 수량을 묶는다. 현재 Paper 비용 가정은 체결 대금보다 작은 비율이므로 매도 비용은 매도 대금에서 지급한다. 실제 체결 비용·가격·호가·정산이 다른 경우의 재검증은 실행 계층에서 반드시 추가해야 한다.

일일 한도는 급격한 시장 이동에 대한 손실 보장이나 손절 주문이 아니다. 시장 가격·비용이 바뀌면 재평가해야 한다. 계좌 일일 순손익 날짜는 KR Asia/Seoul, US America/New_York의 시장 거래일을 따른다. 기존 시장 정책처럼 미국 거래일은 뉴욕 20:00 경계이며, 주문 가능 여부는 별도로 정규 세션에서만 판단한다.

## 검사 결과 재사용과 긴급 정지

결과에는 검사 시각, 가장 빠른 유효시간, controlEpoch, snapshotVersion, 계좌·주문 내용과 예약 후보를 묶는다. 계좌/quote/캘린더/캔들/환율/정규장 종료와 요청 통화 보유분 mark의 만료 중 가장 이른 시각 이후에는 사용할 수 없다. 내부 결과에 계좌 범위가 있으므로 원본 전체를 로그나 공개 API에 출력하지 않는다.

`initialPaperControl()`은 항상 stopped=true, epoch=0이다. `stopPaperControl`은 입력을 변경하지 않고 stopped=true와 증가한 epoch를 반환한다. 안전 정수 상한에서는 정지를 유지하고 추가 승인을 차단한다. 순수 모듈은 자동 해제를 제공하지 않는다. 이후 구현한 Paper DB 원장에서 정지·설정 변경을 영속화하고 복구·한도·lease 재검증 후 명시적으로 resume한다. 데모의 stopped=false는 가짜 정상 사례를 평가하기 위한 입력일 뿐 실행 모드 변경이 아니다.

`isPaperRiskCurrent`는 시간·epoch·snapshotVersion·주문 전체 내용·계좌·전략과 최신 runtime 상태를 다시 확인한다. 중지·원장 변경·실행 장애·주문 변경 후 이전 결과를 재사용하지 않는다. 이것은 내부 순수 함수 결과의 정합성 검사이며 서명 토큰이나 외부 클라이언트의 주문 권한 검증이 아니다. 설정 변경 시에도 epoch를 올려야 한다. 새로운 quote·한도·원장 정보가 오면 전체 리스크 검사를 다시 실행한다.

두 작업이 같은 snapshot을 동시에 검사하면 둘 다 canReserve=true일 수 있다. Paper DB 원장이 계좌 행 잠금 안에서 최신 입력으로 재평가하고 version compare-and-set·영구 unique key·현금/수량 예약을 원자적으로 처리한다. 이 순수 함수와 합성 CLI 자체는 예약을 기록하지 않는다.

## 오프라인 확인

```bash
corepack pnpm risk:demo --output=../../.local-data/risk/risk-demo.json
```

경로는 worker 기준이다. 명령은 `.env`를 읽지 않고 키·DB·네트워크 없이 고정 합성 입력 12개를 검증한다. 계좌 식별자는 출력에서 제외하고, 0600 신규 JSON만 생성하며 기존 파일을 덮어쓰지 않는다. `TRADING_MODE=live`는 거부한다. `.local-data/risk/` 하위이므로 백테스트 리포트 목록과도 섞이지 않는다.

기본 정지·정상 매수·비용 포함 한도·타 전략 현금 예약·수동 보유 보호·자기 물량 매도·기존 매도 예약·중복 매수·일일 손실·수집 장애·미확인 주문·시세 지연을 확인한다. 정상 합성 매수와 자기 소유분 매도 두 사례만 예약 후보가 되고, 정지 후에는 이전 검사 결과가 무효화된다. 예제 종목 코드·가격·한도·비용·수량은 모두 기능 검증용이며 투자 권장값이나 실제 계좌 데이터가 아니다.

## 다음 작업

Paper 계좌·전략·order intent·reservation·control과 영구 중복 키를 구현하고 마이그레이션을 생성했다. 전용 임시 DB에서 동시 예약·정지/lease·복구 조건과 rollback을 검증했다. 내부 Paper 체결·부분 체결·현금/소유권/원가 반영을 추가했다. 상시 worker 복구·관측 갱신은 합성 데이터로 구현했고 로컬 합성 Paper 조회/정지 UI도 추가했으며 소유자 인증·전략 조건/revision 관리도 추가했고 다음은 실제 시세 source 검증이다. 사용자 DB 적용은 검토 후 별도로 수행하며 실제 broker 주문은 계속 비활성으로 둔다.
