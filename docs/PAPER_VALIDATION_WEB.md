# Paper 실행 기록 웹 조회

소유자 로그인 후 `/paper`의 **저장된 Paper 실행 기록** 패널에서 국내·미국 일회성 실행의 요청·종료·정리·대사 증거를 확인한다. 기존 원장 연결 계좌와 별도 기록이며 계좌 ID나 실제 자산을 가져오지 않는다. 실행·재개·정지 조작은 추가하지 않았다.

## 서버 설정과 경계

`PAPER_VALIDATION_ENABLED=false`가 기본이다. 현재 로컬에서 필요한 경우 서버 전용 `.env.paper-preparation`에 `PAPER_VALIDATION_ENABLED=true`를 명시하고 API를 다시 시작한다. 소유자 인증이 설정된 localhost 서버만 허용하며 공개 bind·일반 외부 production 실행은 설정 단계에서 거부한다. production 로컬 컨테이너는 기존 명시적 loopback 모드만 사용한다. 활성화는 DB·토큰·관측·Paper 실행을 시작하지 않는다. 파일 볼륨이나 자료를 자동 복사하지 않는다.

`GET /v1/paper/validation-runs`는 기존 cookie 소유자 인증·loopback·Host/Origin·no-store/private·nosniff 경계를 따른다. query는 빈 객체만 허용하고 body나 URL로 파일 경로·계좌·실행 옵션을 받지 않는다. write endpoint는 없다. 조회 비활성/저장소 접근 실패는 503, 입력 오류는 400, 미로그인은 401이며 오류 원문을 응답/로그에 넣지 않는다.

서버는 고정 `.local-data/paper-validation-runs`를 기존 worker 공개 읽기 전용 helper로 조회한다. CLI와 같은 strict schema·hash·파일 연결·크기/스캔 상한을 사용한다. 공통 JSON 계약은 `packages/contracts`에 두고 원본 계좌·scope·lease·토큰·DB URL·경로·PID·원장 금액·감사 상세는 응답하지 않는다. 현재 프로세스 생존이나 원장 대사 재실행을 수행하지 않으며 모든 executionEnabled/canResume는 false다. [저장 파일 조회의 신뢰/파일시스템 경계](PAPER_VALIDATION_STATUS.md)를 그대로 적용한다. 서버 소유자만 자료를 쓰는 개인용 로컬 환경이며 다중 사용자/상승 권한 파일 서비스가 아니다.

## 표시 규칙

- 국내/미국별 저장 기록을 접어서 표시하고 상세에서 tick 보고값·종료 정리·대사 판정·검사별 passed/failed/unverified를 확인한다. UUID나 반환 순서로 최신 실행을 추정하지 않는다.
- 종료 없는 요청은 **종료 기록 없음**이다. 예정 시각이나 기한 경과로 실행 중·실패·프로세스 생존을 추정하지 않는다.
- 접힌 요약에서도 **실행**과 **검증** 결과를 각각 표시한다. 종료 기록과 완료/실행 상태 보고가 모두 60회인 완료·대사 미완료·대사 문제 기록은 `실행: 60회 실행 완료`로 표시한다. 조기 종료와 시작 전 정지/실패는 해당 상태를 유지한다. 검증은 저장된 verdict만 사용하며 실행 완료를 이유로 승격하지 않는다. 시각 불확실 시 두 상태의 녹색을 모두 숨긴다.
- 실행 상세에서 [구간별 진단](PAPER_RUN_DIAGNOSTICS.md)의 저장 신호·단계·사유를 집계한다. 자료 없음/검증 불가를 구분하고 마지막 진단을 전체 구간의 원인으로 대체하지 않는다.
- `incomplete`와 의도/체결 미검증을 그대로 표시한다. 60 tick이나 원장 보존을 체결·수익성·운용 승인으로 승격하지 않는다. 공통 계약도 모순된 완료/증거 조합을 거부한다.
- 시각 불확실 경고를 완료 녹색보다 우선한다. timestamp는 현재 시세 신선도나 시장 준비도의 보증이 아니다.
- TanStack Query로 10초마다 새로 조회하며 오류/30초 캐시 만료 시 이전 정상 결과를 숨긴다. 조회 새로고침 외 작업 버튼은 없다.
- `rejectedCount`는 누락·검증 거부로 제외한 자료 수이며 실제 실행 실패 수가 아니다. `limited`는 전체 목록을 보장할 수 없음을 표시한다. 원본 오류 문자열과 기술적 내부 플래그를 제품 문구로 노출하지 않는다.

## 검증과 배포

공통 계약·API 입력/인증/접근·worker 조회·프론트 SSR fixture를 검사한다. 합성 fixture 전용 임시 로컬 화면에서 국내 대사 미완료와 미국 종료 기록 없음/예정 시각 표시를 확인했다. 임시 화면은 실제 API·계좌에 연결하지 않았으며 검증 뒤 제거했다. 실제 소유자 로그인 뒤에는 기존 `/paper`에서 저장된 실제 결과를 조회한다.

미국의 이미 승인된 23:35 일회성 실행은 공개 산출물/의존성의 **동일 build hash** 고정 복사본으로 분리했다. 기존 계좌 version·정지 epoch·최대60 tick·기한·재시도 금지를 유지하고 실행 전인 이전 프로세스를 취소한 뒤 교체했다. 소유자 키/환경파일/계좌 자료는 빌드 복사본에 넣지 않았다. 동작 코드를 바꾸거나 고정 build 검사를 생략한 것이 아니다. 대시보드 빌드는 원래 서비스에 적용하며, 실행 프로세스가 참조하는 고정 산출물과 비교 조건은 계속 유지한다.
