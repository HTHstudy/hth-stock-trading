# Paper 통합 리허설

실제 시장 관측과 독립적으로 전략 → 리스크 → 원장 예약 → 부분 체결 → 자산/진단 기록 → 복구를 검증한다. `paper:rehearse`는 실제 증권사 연결을 생성하지 않고 `.env`도 로드하지 않는다. 기본은 계획 미리보기다. 실행 시에도 전용 테스트 DB에 새로운 `paper-rehearsal-<UUID>` 합성 계좌만 만든다. 기존 Paper 계좌 선택·재개·출처 변경은 지원하지 않는다.

## 고정된 검증 조건

버전 관리하는 [계획 JSON](../examples/paper-rehearsal-plan.json)에 조건을 명시한다. 아래 종목 코드와 가격은 시나리오 식별용이며 투자 종목 추천이나 실제 시세가 아니다.

| 조건                                   | 국내                                           | 미국                        |
| -------------------------------------- | ---------------------------------------------- | --------------------------- |
| 검증 대상 / 별도 수동 보유             | 005930 / 000660                                | AAPL / MSFT                 |
| 가상 초기 현금                         | 15,000 KRW                                     | 150 USD                     |
| 별도 수동 보유                         | 3주 × 1,000 KRW                                | 3주 × 10 USD                |
| 평탄 / 상승 교차 / 하락 교차 봉        | 1000·1000·1000 / 1000·900·1100 / 1000·1100·900 | 각 국내 가격의 1/100        |
| 이동평균 / 주문량 / tick당 최대 체결   | 1·2 / 2주 / 1주                                | 동일                        |

금액은 기존 십진 원장과 통화 단위 올림·누적 비용 계산을 사용한다. 합성 체결은 quote 가격을 사용하며 별도 슬리피지 모델은 없다. 매도 비용은 검증용 통합 비용으로 실제 세금·수수료율을 의미하지 않는다. 전체 평가액에는 별도 수동 보유분이 포함된다. 각 시장은 독립 계좌로 검증하고 환전·통화 통합 수익률은 계산하지 않는다.

## 통과 기준

시장마다 독립된 새 계좌 세 개를 사용해 총 13개 항목을 검사한다.

1. 기본 정지 상태에서 주문이 없다.
2. 상승 교차가 매수 예약을 만든다.
3. 첫 체결은 부분 체결 상태다.
4. 두 번째 체결로 매수가 완료된다.
5. 하락 교차 후 두 번의 매도 체결로 왕복 주문 2개·체결 4개 및 예상 현금/평가/손익이 일치한다.
6. 별도 수동 보유 종목의 3주를 유지한다.
7. 자산 이력이 기록된다.
8. 전략 진단이 기록된다.
9. 일부 매수 후 재시작하면 정지 상태로 복구하며 현금·보유량·소유권·가격·일일 손실을 유지한다. 재관측 시각만 비교에서 제외한다.
10. 명시적으로 합성 실행을 재개해도 같은 신호의 주문을 중복 생성하지 않는다.
11. 보유 종목 quote를 180초 지연시키면 신규 실행을 막고 정지·예약 해제·lease 종료한다. 자산은 바뀌지 않는다.
12. 대상 종목을 수동으로 보유한 별도 계좌에서는 `DUPLICATE_BUY`로 매수를 거부한다.
13. 해당 계좌의 하락 교차로 수동 보유분을 매도하지 않는다.

매수와 매도를 발생시키기 위해 독립된 3봉 입력 프레임을 교체하고 각 프레임의 시각을 DB 현재 시각에 맞춘다. 캘린더도 KR/US 거래일 규칙과 DST를 따르는 **가상 세션**이다. 실제 휴장일 검증, 연속 봉 재생, 역사 데이터 백테스트, point-in-time 재현 또는 전략 수익성 검증이 아니다. 봉 종료 여부는 기존 `prepareStrategyData`가 판정한다. 실행 중 어느 시장의 거래일이라도 바뀌면 `PAPER_REHEARSAL_DAY_CHANGED`로 중단하므로 일자 경계를 지난 뒤 새로 실행한다.

## 실행

Node 24와 `corepack pnpm`을 사용한다. 기본 명령은 DB나 키 없이 계획과 `planHash`만 출력한다.

```bash
corepack pnpm paper:rehearse
```

실행에는 별도 임시 PostgreSQL이 필요하다. 기존 개발·대시보드 DB를 지정하지 않는다. 아래 컨테이너는 로컬 테스트용 자격증명과 빈 전용 DB를 사용하고, 포트는 Docker가 빈 포트를 배정한다.

```bash
docker run --rm --detach --name hth-paper-rehearsal \
  --env POSTGRES_USER=hth_test --env POSTGRES_PASSWORD=local_test_only \
  --env POSTGRES_DB=hth_readonly_test --publish 127.0.0.1::5432 postgres:17-alpine
docker port hth-paper-rehearsal 5432
```

표시된 포트를 아래 `<PORT>`에 넣는다. PostgreSQL 준비 후 최초 한 번 `--prepare`로 **이 전용 DB만** 마이그레이션한다. 다음 실행은 `--prepare`를 생략해도 된다. 매번 새 계좌를 만들고 기존 데이터를 삭제하지 않는다.

```bash
PAPER_REHEARSAL_DATABASE_URL=postgresql://hth_test:local_test_only@127.0.0.1:<PORT>/hth_readonly_test \
  corepack pnpm paper:rehearse --execute --prepare

docker stop hth-paper-rehearsal
```

`PAPER_REHEARSAL_DATABASE_URL`만 사용하며 일반 `DATABASE_URL`로 대체하지 않는다. localhost·전용 DB명·전용 role과 실제 접속 DB/role을 검사한다. URL query/hash와 `TRADING_MODE=live`, 알 수 없는 옵션을 거부한다. 계획 파일은 일반 파일·64KiB 이하·strict schema로 제한한다. `--plan <경로>`, `--output <디렉터리>`로 로컬 입력/출력 위치를 지정할 수 있다. 새 의존성이나 DB 스키마 변경은 없다.

## 결과와 다음 단계

`.local-data/rehearsals/<UUID>/report.json`에 계획 원본·계획 hash·검증 결과·합성 잔액을 저장한다. 디렉터리는 0700, 파일은 0600으로 생성하고 임시 파일에서 원자적으로 교체한다. 인증 정보·DB URL·계좌 ID·원본 예외를 저장하지 않는다. 정상/실패/취소를 구분하며 실패 시 완료된 검사와 허용된 오류 코드만 기록한다. worker는 성공·실패 모두 종료하며 활성 lease를 정리한다.

`semanticHash`는 계획 hash와 순서가 고정된 검사/금융 결과만 포함한다. 실행 UUID·시각·DB 행 ID는 제외하므로 같은 계획을 다시 실행하면 동일해야 한다. 전체 원장/파일의 바이트 단위 재현성은 보장하지 않는다. 이 리포트는 현재 대시보드에 연결하지 않으며 실행 상태는 CLI/JSON에서 확인한다.

리허설 통과는 실거래 승인이나 실제 시세 Paper 재개가 아니다. 후속 작업은 국내·미국 관측 결과 검토, 실제 시세 Paper의 종목·전략·가상 자금·손실 한도를 별도로 고정, 정지 상태 관측/대사 확인, 제한된 시간의 Paper 운영 검증이다. 현재 1·2 이동평균과 종목/한도는 엔진 검증값이며 사용자의 투자 전략으로 확정하지 않는다.

## 구현 검증 기록

2026-10-30 별도 임시 PostgreSQL에서 전체 테스트 387개를 통과했다. CLI 미리보기와 26개 검사 통과 리포트를 확인했고, 반복 실행의 `semanticHash`가 일치했다. 리포트의 0700/0600 권한과 비공개 연결 정보 미포함도 확인했다. 테스트는 외부 fetch 호출이 없음을 검사하며, 오류 후 lease 정리와 시작 전 취소도 검증한다. 실제 계좌 주문이나 기존 Paper 계좌 재개는 수행하지 않았다.
