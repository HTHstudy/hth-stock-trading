# Paper 전략 실행 진단

## 목적과 화면

Paper 화면의 **전략 신호·주문 차단 진단**은 worker가 실제 실행 중 저장한 결과를 보여준다. 신호 BUY/SELL/HOLD, 평가 생략, 필요한 봉 부족, 교차 없음, 기존 소유분, 같은 봉 중복 의도, 실제 리스크 거부와 예약 상태를 구분한다. 등록 활성·계좌 정지·worker lease는 현재 상태로 별도 표시한다.

진단은 당시 기록이다. 조회로 시세를 수집하거나 전략/리스크를 재평가하지 않고 주문·체결·재개도 수행하지 않는다. 신호만으로 주문이 생성됐거나 체결됐다고 해석하지 않는다. 기록이 없으면 미평가/범위 밖으로 표시하며 HOLD나 미매수 원인을 추정하지 않는다. 봉 검증을 하지 않았으면 봉 수는 null이다. 60초 이상 된 기록과 현재 설정 revision/version이 다른 기록에는 경고한다.

등록 비활성 전략은 실행기에서 제외하므로 새 진단이 없을 수 있다. 정의가 없는 과거 전략은 신뢰된 서버 런타임 조건으로 실행하던 기존 경로를 유지하며, 저장 조건을 새로 만들어 추정하지 않는다. 현재 설정과 과거 진단을 함께 보여주되 과거 조건을 현재 값으로 바꾸지 않는다.

## 기록 방식

기존 불변 `paper_events`에 STRATEGY_DIAGNOSED 묶음을 저장한다. 별도 테이블·마이그레이션·의존성은 없다. 묶음에는 정책 버전, 기록 시각, 출처, 원장 version/epoch, 전략별 평가 시각·revision·대상·단계·신호·허용된 사유·종료 봉 수/시각·당시 모의 주문 상태와 내용 hash를 저장한다. 가격·현금·보유 수량·계좌 식별자·원본 API/예외는 진단 데이터에 넣지 않는다.

worker가 실행 제어·입력 검증·전략 평가·예약의 실제 결과를 수집한다. 정지/휴장은 평가를 생략한 사실을 기록한다. 입력 차단은 실제 `prepareStrategyData` 사유를 보존한다. 리스크 거부는 실제 DB 예약 결과를 사용한다. source/체결/실행 오류는 단계와 허용된 일반 코드만 최선 노력으로 남긴다. 초기화 실패, 소유권 상실, 진단 저장 장애에는 기록을 보장하지 않으며 이전 진단을 현재 실패 원인으로 단정하지 않는다.

기록은 계좌 행 잠금 안에서 lease/token/epoch·출처·전략 revision/version/대상·평가 시각을 확인한다. 진단 저장은 원장 version·현금·예약·체결·제어 상태를 변경하지 않는다. 동일 의미의 진단은 30초 안에 반복 저장하지 않고 단계·신호·사유·봉·설정·epoch가 바뀌면 바로 기록한다. 기록 누락을 거래 진행 사유로 쓰지 않는다. 정상 실행의 진단 저장이 실패하면 기존 오류 종료 경로로 정지·잔여 예약 정리를 수행한다. 원래 예외를 진단 저장 예외로 덮어쓰지 않는다.

주문 의도/예약 트랜잭션과 진단 트랜잭션은 별도다. 두 기록의 원자적 동시 저장을 보장하지 않는다. 장애 시 이미 커밋된 의도는 원래 감사/주문 이력에서 확인하고 기존 복구 경로로 처리한다. 진단은 주문 원장이나 실행 권한을 대체하지 않는다.

## 조회 경계와 한계

`GET /v1/paper/diagnostics`는 소유자 인증·localhost·서버 고정 계좌·기존 Paper 기능 활성화를 요구한다. query와 계좌 선택을 받지 않는다. 읽기 전용 repeatable-read snapshot/3초 statement timeout 안에서 현재 전략 최대 100개와 최근 진단 묶음 20개를 읽고, 전략별 마지막 기록을 제공한다. 더 오래된 묶음/전략이 있으면 limited=true다. 범위에서 찾지 못한 결과는 null이다. 계좌별 감사 인덱스를 사용하며 진단 이벤트는 일반 거래/실패 이력 목록에서 제외해 반복 진단으로 운영 이벤트를 가리지 않는다.

내용 hash·strict schema·출처·version/epoch 상한을 검증하고 불일치/저장소 오류는 원문 없이 503 PAPER_DIAGNOSTICS_UNAVAILABLE로 차단한다. hash는 내용 변경 검사이며 평가 알고리즘의 진위나 기록 완전성을 공증하지 않는다. 브라우저에는 계좌 ID·token·epoch·원장 version·hash·감사 원문을 보내지 않는다. 화면은 5초마다 읽으며 조회 실패 시 오래된 결과를 정상 최신값으로 표시하지 않는다.

실제 broker 장애의 구체적 원인, 모든 시작/취소/장애의 완전한 기록, 여러 전략 중 첫 실패 뒤 평가되지 않은 전략의 결과, 장기 보존·통계 집계는 보장하지 않는다. 실제 주문·외부 배포와는 연결하지 않는다.

## 검증

가짜 시세와 임시 DB에서 정지 평가 생략, BUY 예약/부분 체결, 기존 보유, HOLD warmup, 시세 지연, 리스크 거부, 같은 봉 중복, source 오류 원문 제외, 반복 저장 억제와 진단 저장 장애 시 정지를 검증한다. DB는 소유권/출처/revision 거부, 설정 변경과 과거 기록 구분, 계좌 분리, hash 불일치, 불변성, 조회 범위와 원장 무변경을 검증한다. 실제 사용자 Paper 계좌를 재개하거나 진단을 만들기 위한 합성 데이터를 주입하지 않는다.

전체 351개 테스트와 타입·린트·빌드·포맷 검사를 통과했다. 렌더링에서 기록 없음·봉 부족·리스크 거부·오래된 설정 경고를 확인했다. 실제 로컬 인증 API에서는 기존 계좌의 진단 없음과 조회 전후 정지·자산·주문 유지, 비공개 필드 제외를 확인했다. 별도로 실행 중인 정규장 읽기 전용 관측에는 연결하거나 영향을 주지 않았다.
