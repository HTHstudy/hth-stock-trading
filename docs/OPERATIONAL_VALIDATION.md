# 실제 시세 운영 검증

## 현재 단계

읽기 전용 연동, 백테스트, Paper 원장/실행기, 로컬 관리 화면은 구현했다. 현재는 실제 시세 반복 관측과 차단 사유 검토 단계다. 실제 시세 관측 성공을 Paper 체결·계좌 대사·실거래 검증 완료로 해석하지 않는다. 실제 주문과 외부 배포는 별도 작업이다.

이 문서는 사람이 확인한 증거와 아직 확인하지 않은 항목을 구분한다. 자동 승인이나 거래 재개 기능은 없다. 수집 정책·오류 처리·저장 형식은 [관측 정책](MARKET_OBSERVATION.md)을 따른다.

## 검증 순서

| 순서 | 확인할 내용         | 증거와 완료 기준                                             | 현재 상태                                       |
| ---- | ------------------- | ------------------------------------------------------------ | ----------------------------------------------- |
| 1    | 읽기 전용 연결      | 실제 KR/US 관측의 종료 리포트와 검증된 journal               | 단발 연결 확인 완료                             |
| 2    | 반복 수집·파일·화면 | 여러 번 수집한 기록의 순서·간격·해시·합계, 인증된 상세 조회  | 2026-10-29 완료                                 |
| 3    | KR/US 정규장        | 각 시장 정규장 중 반복 관측, 지연·종료 봉·차단 원인 검토     | 10/30 국내 재관측 시작·미국 재예약; 완료 미검증 |
| 4    | 세션/날짜 경계      | 개장 전후·정규장 종료 전후·휴장·거래일 변경의 실제 기록      | 미검증                                          |
| 5    | 프로세스 수명       | 실제 수집 중 정상 취소·잠금 해제·후속 실행, 장시간 토큰 갱신 | 잠금 경합·정상 종료 후 해제 확인; 나머지 미검증 |
| 6    | Paper 운영          | 출처가 확인된 전용 모의 계좌의 한도·일일 검토·복구·내부 체결 | 실제 시세 장시간 운용 미검증                    |

정규장 관측은 시장별로 분리한다. 첫 진단은 60초 간격 60회 정도로 시작할 수 있지만 횟수만 채워도 합격하는 기준은 아니다. 수집 시간이 더해지므로 실행 시간은 정확히 1시간이 아니다. 모든 차단을 없애기 위해 신선도·세션 정책을 완화하지 않는다. 휴장 중 오래된 시세나 정규장 밖 봉을 수집할 수 있으며, 수집 성공과 전략 입력 적합성을 구분한다.

## 실행과 검토

```bash
# 기존 .env의 읽기 전용 설정 사용. Paper 계좌·재개 옵션 없음
corepack pnpm market:observe --symbols=KR:005930 --samples=60 --interval-seconds=60
corepack pnpm market:observe --symbols=US:AAPL --samples=60 --interval-seconds=60
```

위 코드는 수동 실행 예시다. 사용자 요청에 따라 이번에는 확인한 다음 정규장에 한정된 1회 대기 프로세스를 실행한다. OS 상시 스케줄러·자동 재시작은 등록하지 않는다. 종목은 연결 검증용 예시이며 사용자 전략·관심종목을 변경하지 않는다. 실제 일정과 세션은 각 실행에서 수집한 캘린더로 확인한다. [예약과 세션 검사](MARKET_OBSERVATION.md)를 따른다.

1. 기존 실행과 같은 토큰 잠금 DB를 사용하고 겹치는 새로고침·수집을 피한다. 읽기 전용 수집 중의 `BROKER_LEASE_BUSY`는 주문 권한이나 토큰 재발급 우회 사유가 아니다.
2. 종료 후 run ID, 시작/종료 시각, 출처, 종목, 요청/기록 수, 오류와 차단 사유를 검토한다. `completed`는 반복 종료를 뜻하며 정상 데이터 판정과 다르다.
3. 소유자 로그인 후 **시세 관측**에서 해당 ID의 상세가 열리는지 확인한다. 이 API는 schema·journal hash·집계를 다시 검증한다. 미완료나 검증 실패를 정상 기록으로 채택하지 않는다.
4. 가격·원본 시세·계좌·인증 정보를 검증 문서에 복사하지 않는다. 로컬 결과는 Git에서 제외하고 문서에는 허용된 요약과 run ID만 남긴다.
5. 다음 단계 전에 부족한 시장/세션/수명 증거를 확인한다. 실제 통신 장애를 만들기 위해 API 키·허용 IP·기존 DB나 네트워크를 변경하지 않는다. 오류·timeout·취소 경로는 가짜 source 테스트로 먼저 확인한다.

원장은 사용하지 않았으며 계좌·주문 API, Paper 재개, 전략/관심종목 변경, 업무 DB 마이그레이션을 수행하지 않았다. 실제 시세는 수신했지만 가격·원본 캔들은 관측 파일에 저장하지 않았다.

journal의 10개 순서와 각 완료 후 다음 시작까지의 30초 간격, SHA-256, 파일 권한(디렉터리 0700/파일 0600), 인증된 목록/상세 API의 완료 상태와 재집계를 확인했다. 종료 전에는 API가 미완료로 표시하고 journal을 노출하지 않는 것도 확인했다. 실행 중 동일 client의 추가 작업은 BROKER_LEASE_BUSY로 진입하지 못했고, 종료 뒤 동일 잠금을 다시 획득·해제할 수 있었다. 이 잠금 확인에는 토큰 발급을 호출하지 않았다. Paper는 정지 상태다.

관측·파일·설정·리포트 관련 가짜 source 테스트 27개가 통과했다. 로컬 결과는 `.local-data/observations/<runId>/`에만 보존하며 Git에는 문서 요약만 기록한다. 이 실행은 정규장 밖 반복 수집 검증이다. 정규장·세션 경계·실제 통신 중 취소·장시간 토큰 갱신·Paper 장시간 운용은 아직 검증하지 않았다.

### 다음 정규장 1회 예약과 장애 복구 검증

2026-10-29 토스 캘린더의 국내 다음 영업일과 미국 오늘 정규장을 조회했다. 미국은 10월 29일 22:35 KST(13:35 UTC), 국내는 10월 30일 09:05 KST(00:05 UTC)에 각각 60회·완료 후 60초 간격으로 관측하도록 로컬 대기 프로세스를 실행했다. 시작 시 새 캘린더를 재확인한다. 등록 당시 두 작업 모두 `waiting`이었으며 정규장 검증을 완료한 상태가 아니었다. 이후 결과는 아래 10월 30일 점검을 따른다.

예약 실행 기록은 `.local-data/scheduled-observations/us-2026-10-29/launch.json`, `kr-2026-10-30/launch.json`에 PID·예정 시각·종목·실행 파일 hash를 저장했고, 각 `process.log`에서 대기/실행 종료/허용된 실패 코드를 확인한다. launch.json은 시작 시 기록이며 실시간 상태가 아니다. 대기 중 토큰 잠금을 점유하지 않는 것을 확인했다. 로그의 최종 runId로 관측 화면에서 결과를 검토한다. PC/DB가 꺼지거나 절전으로 시작을 놓치면 완료를 보장하지 않는다. 반복 일정과 OS 서비스는 등록하지 않았다. 취소하려면 해당 PID가 이 관측 프로세스인지 확인한 뒤 SIGTERM을 보낸다.

장 시작을 기다리는 동안 합성 source와 별도 임시 PostgreSQL에서 부분 체결 후 통신 장애·기본 정지 재시작·명시적 재개를 연속 검증했다. 같은 봉 주문은 1개, 체결은 1개로 유지됐고 미체결 잔량은 중단됐다. 오래된 quote와 수집 중 긴급 정지 뒤 늦은 정상 응답도 추가 체결을 만들지 않았다. 실제 Paper 계좌를 재개하지 않았다. 전체 324개 테스트와 타입·린트·빌드·포맷 검사가 통과했다. 별도 CLI 실행으로 예약 대기 중 취소·시작 시각을 놓친 종료가 DB/관측 파일 생성 전에 끝나는 것도 확인했다.
