# 세션·토큰 관측 묶음 준비

2026-11-04 15:34 KST 무렵에 동일 broker 잠금 DB/client 안에서 국내·미국 공식 캘린더를 조회했다. 기존 미국 Paper 예약과 겹치지 않는 세션/토큰 관측 후보를 한 묶음으로 계산했다. 시각은 모두 KST다. 새 장시간 관측을 시작하거나 예약한 기록은 아니다.

공식 캘린더의 미국 개장 11/4 23:30을 기준으로 한 관측 창 23:25~23:40은 Paper 예약과 겹쳐 RESERVED_WINDOW_OVERLAP으로 제외했다. 국내·미국 세션 후보의 전체 창과 기존 Paper 예약을 토큰 계획의 예약 입력에 함께 포함했다. 앞 작업의 정리/잠금 해제를 확인하지 않고 다음 작업을 시작하지 않는다.

토큰 계획은 이번 실제 조회에서 관측한 TTL 86,399초를 기준으로 계산한 후보이며 미래 TTL을 보장하지 않는다. 실행 시의 반환 TTL·후속 읽기·expiry 성공과 종료 증거를 별도 검토해야 한다. 하루 이상 같은 client 잠금을 점유하므로 해당 창의 다른 실제 시세/Paper 작업과 외부 인증 도구도 추가 검토해야 한다.

## private 증거

- 공식 캘린더/안전한 토큰 계측·Paper 전후 보존: `.local-data/observation-readiness/153b3f38-e3df-46ae-85d1-fa6af4b57d4e/result.json`
- 전체 후보·제외 사유·입력/출력·binding hash: `.local-data/readonly-validation-batches/63423c22-e92f-4e30-8186-afed1ce7469e/plan.json`

자료는 새 UUID/0600으로 생성했고 내용 hash를 보관했다. 준비 KR/US Paper 원장은 조회 시각을 제외한 전후 hash가 같았다. 일일 기준·전략·자금·관심종목·원장·기존 예약을 변경하지 않았다. 증권사에는 캘린더만 읽었으며 실제 주문은 구현/호출하지 않았다.

## 병행한 개발

[예약 감사](PAPER_RESERVATION_AUDIT.md)에서 제외된 과거 기록의 원인을 조사하고, [감독기 상태 조회](READONLY_SUPERVISION_STATUS.md)를 별도 에이전트가 구현했다. main은 실제 캘린더와 예약 충돌 계산·private 증거·통합 검증을 담당한다. 작업 파일을 분리하고 커밋/푸시는 main에서 통제한다.

상태 조회는 다음 명령으로 확인한다. 조회로 자식·DB·토큰·시세 요청을 생성하지 않는다.

```bash
corepack pnpm readonly:supervision:status
```

실행 준비는 [유한 감독기](READONLY_SUPERVISOR.md)의 계획/종목/출처/예약 시각·코드 hash 검사를 따른다. 고정 코드와 실행 환경, 최신 전체 예약 검토, 앞 작업의 정상 종료·잠금 정리, Paper 원장 보존 기준을 확인한 뒤에만 실제 관측을 연결한다. 이 묶음의 hash나 계획 미리보기로 Paper 재개·실거래를 승인하지 않는다. 자동 연장·다음 날 이월·실패 재시도는 하지 않는다.

## 현재 차단과 재발 방지

과거 `a4072920-6191-48e9-bc0e-76def63dd4a0`에는 result.json만 있고 request.json이 없다. [예약 감사](PAPER_RESERVATION_AUDIT.md)는 이를 request-missing-or-null로 분류하며 예약 무시 권한을 주지 않는다. 새 감독기의 실제 시장 관측은 이 미확인 기록 때문에 계속 차단된다. 표의 세 후보는 이 차단을 해제한 실행 예약이 아니다. 기존 미국 Paper 예약은 별도 고정 코드에서 유지된다.

재발 방지를 위해 향후 Paper 실행기는 이미 검증된 요청을 새 UUID에 먼저 기록하고 그다음 두 번째 빌드 검사를 수행하도록 순서를 보완했다. 빌드 변경 실패에도 요청과 종료 기록이 연결되도록 한 수정이다. 현재 대기 중인 고정 빌드/과거 증거를 바꾸거나 실패를 재실행하지 않았다. 파일 쓰기 자체가 실패하는 장애까지 정상 기록을 보장하지 않는다.

## 통합 검증
