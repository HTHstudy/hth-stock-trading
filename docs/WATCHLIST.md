# 대시보드 관심종목 관리

## 범위와 기본값

계좌 현황의 **관심종목 관리**에서 국내/미국 종목 코드를 추가·삭제하고 저장한다. 종목명 검색/자동완성은 아직 없으며 정확한 코드/티커를 직접 입력한다. 저장은 코드 형식 검증이며 증권사에서 존재/거래 가능 여부를 확인한 결과가 아니다. 다음 시세 조회가 실패해도 관리 화면에서 다시 수정할 수 있다.

관심종목은 **웹 대시보드에서 조회하는 종목**이다. Paper 전략의 대상·조건·활성 상태, 기존 보유분, 백테스트 입력, `market:observe`/수집 CLI의 종목 설정은 변경하지 않는다. 저장으로 인증·시세 수집·거래·worker 재개를 시작하지 않는다. 추가한 종목을 자동 매수하거나 삭제한 종목을 자동 매도하지 않는다.

저장 파일이 없으면 서버 READONLY_SYMBOLS를 초기 목록으로 표시한다. 환경변수도 없으면 기존 검증용 기본값 KR:005930/US:AAPL을 표시하며 투자 추천/확정 매매 대상이 아니다. 직접 저장한 뒤에는 저장 목록이 대시보드 조회에 우선한다. 빈 목록을 저장해도 기본 종목을 다시 채우지 않는다.

최대 20개이며 코드의 앞뒤 공백을 제거하고 영문을 대문자로 정규화한다. 영문·숫자·점·하이픈 1–40자만 허용한다. 현재 broker의 심볼 식별 제한에 맞춰 시장이 달라도 같은 심볼 문자열은 중복으로 거부한다.

## 저장과 조회 반영

1. 소유자 로그인 후 계좌 현황에서 **관심종목 관리**를 연다.
2. 시장/코드를 편집하고 저장한다. 전체 삭제도 가능하다.
3. 저장 확인 후 상단 **새로고침**으로 새 목록의 시세를 조회한다. 기존 최소 30초 조회 간격은 유지한다.

저장이 확인되면 API는 기존 계좌/시세 snapshot과 진행 중 조회를 무효화한다. 화면은 마지막 결과의 종목을 새 목록으로 오해하지 않도록 새 조회 전까지 비운다. 취소된 조회가 늦게 반환돼도 새 캐시에 반영하지 않는다. 저장 자체가 새로고침을 실행하지 않는다. 관심종목이 비어 있으면 다음 새로고침은 계좌/보유분/환율 조회를 유지하면서 종목 메타데이터·현재가·캔들 조회를 생략한다. 보유분을 관심종목으로 자동 편입하지 않는다.

## 보관 방식과 충돌

서버 고정 `.local-data/settings/watchlist.json`에 형식 버전·revision·시장/코드만 보관한다. 계좌번호·인증 정보·전략 정의는 포함하지 않는다. 조회는 디렉터리/파일을 생성하지 않으며, 첫 저장 시 디렉터리 0700·파일 0600으로 만든다. 기존 상위 디렉터리 권한은 바꾸지 않는다.

MVP에서는 키/업무 DB 없이 편집하고 서버 재시작 후에도 유지하기 위해 파일 저장을 선택했다. 기존 환경변수를 수정하거나 사용자 DB에 마이그레이션하지 않는다. 새 의존성은 없다. 향후 운영 저장소 변경은 read/save 계약과 UI를 유지하며 별도 검토할 수 있다. 파일은 Git에서 제외되므로 서버 이전/백업 시 설정 디렉터리도 포함해야 한다.

모든 작성자는 같은 watchlist.lock을 배타적으로 생성한 뒤 현재 revision을 재확인한다. 임시 파일을 작성·sync하고 rename으로 교체한다. 다른 창의 오래된 expectedRevision은 409 WATCHLIST_REVISION_CONFLICT로 거부한다. 동시에 저장 중이면 WATCHLIST_BUSY로 거부한다. UI는 저장을 자동 재시도하지 않고 충돌/불확실한 응답에서는 최신 목록을 다시 읽어 편집하도록 안내한다.

프로세스 강제 종료로 lock이 남으면 자동으로 제거하거나 강제 저장하지 않는다. 같은 설정 디렉터리를 사용하는 모든 API 프로세스가 중지됐는지 확인하고, 저장 파일을 백업/검토한 후 남은 lock을 정리해야 한다. 실행 중인 작성자의 lock을 지우지 않는다. 전원 장애 시 디렉터리 메타데이터까지 완전한 내구성을 보장하는 저장소는 아니며, 불확실한 저장은 실제 파일의 revision을 재조회한다. 설정 변경 이력/복원 UI는 후속이다.

저장 파일이 손상됐거나 심볼릭 링크/일반 파일이 아니거나 16KiB를 넘으면 초기 목록으로 조용히 대체하지 않고 실패한다. 로컬 OS 사용자 신뢰 경계이며 관리자에 의한 직접 파일 편집/삭제까지 CAS로 막지는 않는다. 파일 삭제는 초기 목록으로 되돌아가는 동작이므로 정상적인 빈 목록 저장을 대신하지 않는다.

## API와 worker 경계

- `GET /v1/watchlist`: revision·origin(environment/saved)·정규화한 목록
- `POST /v1/watchlist`: `{ expectedRevision, instruments }`만 허용

두 경로는 소유자 인증과 기존 localhost/Host/Origin 경계를 요구하고 POST에는 대시보드 전용 헤더가 필요하다. 파일 경로·계좌·실행/전략 옵션은 받지 않는다. no-store/private로 응답하고 비밀번호·계좌·원본 오류를 반환/로그에 출력하지 않는다. 외부 배포에는 활성화하지 않는다.

API는 새로고침 시 저장 목록을 다시 읽고 서버 전용 DASHBOARD_WATCHLIST_JSON 환경값으로 조회 child에 전달한다. worker는 같은 Zod 계약으로 검증하며, 빈 목록을 환경변수 기본 종목으로 바꾸지 않는다. 키/DB 연결 검증과 목록 검증을 분리하여 기존 CLI 설정은 유지한다. 실제 증권사 통신과 토큰 발급 잠금은 기존 읽기 전용 worker가 소유한다.

검증은 임시 설정 디렉터리·가짜 child/fetch로 초기 조회 무변경, 재시작/빈 목록 보존, 동시 저장/리비전 충돌, 손상/링크/남은 잠금, 인증/CSRF/입력 주입, 캐시 무효화/늦은 응답 폐기, 빈 목록의 종목 조회 생략을 확인한다. 테스트에서 실제 증권사 요청이나 사용자 관심종목 변경을 수행하지 않는다.
