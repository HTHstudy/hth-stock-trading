# 웹 테마

화면 상단의 시스템 / 라이트 / 다크 버튼으로 바꾼다. 로그인 전과 후에 모두 사용할 수 있다. 기본은 OS 설정이며 명시적으로 선택한 라이트·다크가 OS보다 우선한다. 시스템 선택 중 OS 테마가 바뀌면 화면도 갱신한다.

선택은 브라우저 localStorage의 `hth-theme`에만 저장한다. 계좌·인증·서버 설정과 무관하며 테마 변경으로 조회 새로고침·시세 수집·거래를 시작하지 않는다. 저장소 접근이 차단되면 현재 탭에서 선택을 유지하되 새로고침 후 저장은 보장하지 않는다. 같은 origin의 다른 탭 변경·키 삭제도 반영한다.

`public/theme-init.js`를 HTML head에서 먼저 실행해 저장된 테마를 React 시작 전에 적용한다. 초기화 스크립트를 로드하지 못하면 CSS의 다크 기본값이 먼저 나타날 수 있다. React의 ThemeProvider는 화면 상태, OS 변경과 저장 이벤트를 관리하고 리스너를 정리한다. 추가 의존성 없이 React와 브라우저 API를 사용한다.

색상은 `app/global.css`의 의미별 토큰으로 관리한다. 페이지는 `bg-surface`, `text-primary`, `text-muted`, `text-warning` 등 역할을 사용하며 개별 화면에 다크 전용 배경을 직접 고정하지 않는다. 새 화면도 같은 토큰을 사용한다. 손익 표시는 기존 국내 관례인 상승 빨강·하락 파랑을 유지한다.

Lightweight Charts의 세 화면은 공통 `shared/lib/chart-theme.ts` 팔레트를 사용한다. 테마 변경에는 `applyOptions`로 색만 바꾸며 차트를 제거하거나 `fitContent`로 범위를 초기화하지 않는다. 데이터 자체가 바뀔 때 차트를 다시 만드는 기존 정책은 유지한다.

검증은 저장 값 우선순위·잘못된 값의 기본 처리·저장소 차단·초기 HTML 적용을 자동 검사하고, 기존 인증/라우팅/연구/원장 표시 회귀와 구분한다. 브라우저에서 연구 화면의 라이트/다크 전환과 새로고침 후 선택 유지를 확인했다. 412px 모바일에서 버튼·텍스트·경고·리포트 선택 표시를 확인했고 검증 후 기기 에뮬레이션과 개발자 도구를 원복했다. 로그인 화면에서도 라이트 선택이 유지됐다. OS 설정의 실제 변경과 차트 확대 범위 보존은 코드 검토를 거쳤으나 브라우저 조작으로 직접 검증하지 않았다.

2026-11-09 새 일회용 localhost 전용 DB에서 로컬 `verify:ci`의 125파일·943개 테스트(51.95초), 포맷·린트·타입·전체 빌드가 통과했다. 원격 Actions 결과는 아니다. 사용한 임시 DB만 종료하며 업무·Paper DB는 변경하지 않는다.
