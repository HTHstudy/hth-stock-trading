# Paper 미확인 예약 정책 검토 — 2026-11-10

## 결론과 검토 범위

a407(`a4072920-6191-48e9-bc0e-76def63dd4a0`)은 연결된 당시의 독립 소유 launch/exit 자료가 없고, 기한 경과와 실행 전 중단·0 tick이라는 종료 파일의 자기 보고만으로는 **현행 규칙에서 예약 차단을 해소할 수 없다**. 기다림, 현재 정지 상태, 다른 run의 정상 종료는 대체 근거가 아니다. 이 문서는 정책 검토이며 차단 해소 완료, 예외 권한 부여, 실행·재개·실거래 승인이 아니다.

검토 근거는 [AGENTS.md](../AGENTS.md), [예약 감사](PAPER_RESERVATION_AUDIT.md), [원본 보존형 예약 정리](PAPER_RESERVATION_CLOSURE.md), [실거래 준비 현황](LIVE_READINESS.md)이다. a407의 사실관계와 수치는 이 문서들에 기록된 과거 확인 결과를 인용한다. 원본 구성·종료 파일의 상세 사실은 과거 기록을 인용하며 이를 새로 재측정했다고 표현하지 않는다. 아래 현재 파일 기반 예약 집계와 구분한다.

코드·기존 문서의 검토와 함께 11월 10일 파일 기반 예약 조회는 available·limited=false·rejectedCount=1·unresolvedCount=1·retiredCount=0·awaiting-result 0건을 반환했다. 현재 프로세스 생존이나 DB 원장을 확인한 결과가 아니다. 실제 운영 DB·키·시세·관측·프로세스 제어·예약 처리 기록·마이그레이션은 수행하지 않았다. 같은 작업에서 추가한 [고정 설정 합성 복구 검사](PAPER_FIXED_SETTINGS_VALIDATION.md)는 별도 범위이며 a407의 종료 근거로 쓰지 않는다.

## 실제 종료 자료의 유무에 따른 조건

### 당시 자료가 실제로 존재하고 확보 가능한 경우

현행 경로는 a407 자체에 연결되는 **당시 직접 소유한 프로세스의 독립 자료**를 검토하는 것이다. 향후 별도 승인 범위에서 자료를 확보하더라도 다음 조건을 모두 충족해야 하며, 이번 문서는 확보 가능성이나 유효성을 확인하지 않았다.

1. 원본은 `result.json`만 있고 request/before/after/review가 없는 지원 범위여야 한다. 정확한 파일 집합·바이트 수·SHA-256을 고정하고 파일 추가·내용 변경·symlink·16KiB 초과를 거부한다.
2. terminal은 `stopped-before-run-or-failed`, `waiting`, `runStarted=false`, `completedTicks=0`, `PAPER_BUILD_CHANGED`여야 한다. 실행 tick·의도/체결·대사 verdict나 다른 단계·오류를 지원 범위에 끼워 넣지 않는다.
3. launch의 runId와 실제 run-id 인수, exit의 launchId/runId/nonce/launchHash, exit 본문 hash가 연결돼야 한다. 직접 보유한 ChildProcess의 close/error에서 수집한 자료여야 하며 PID 재연결·수동 확인은 대체 수단이 아니다.
4. 강제 종료가 아니고 `signal=null`, `exitCode=1`이어야 한다. `launch ≤ terminal ≤ 직접 관찰한 exit ≤ 현재 시각`과 허용 시각 정밀도를 검증한다. exit code 1 하나만으로 정리를 허용하지 않는다.
5. 계획 hash를 고정한 뒤 별도 적용에서 최신 원본·증거를 다시 검증하고, 별도 처리 기록만 새로 만든다. 적용 전후 및 후속 예약 검사에서 변경·읽기 실패·상한 초과가 있으면 차단한다.
6. 해당 한 건의 현재 예약 처리 범위만 다룬다. 과거 rejectedCount·실패·원본·다른 미확인 기록과 충돌을 보존하고, 원장·계좌 안전성·재개는 별도로 판단한다.

### 당시 자료가 실제로 없거나 확인할 수 없는 경우

현행 closure를 성립시킬 방법이 없다. 새 wrapper로 지금 실행해 얻은 종료, 현재 PID 검색, 시간이 지난 사실, 계좌 정지, 반복 inspect, hash 재계산으로 과거의 소유 launch/exit를 생성하거나 대체할 수 없다. 새로운 실행으로 증거를 만들려고 시도하는 것도 a407의 과거 증거 확보가 아니다.

따라서 a407은 미검증·차단으로 남긴다. 감사 문서가 명시하듯 더 기다리면 자동 해제되는 문제로 분류하지 않는다. 남은 선택 범위는 실제 존재하는 당시 자료의 확보 가능성 확인 또는 별도 정책 재설계 검토이며, 자료가 없는데 차단을 없애는 변경은 현행 허용 조건을 바꾸는 작업이다. 이번 작업에서는 어느 쪽의 실행도 승인하거나 수행하지 않는다.

## 미래 세대 격리·실행 권한 fencing의 재설계 검토 조건

## 병렬 검증 및 실거래 준비와의 경계

기존 5/20·1주 고정 plan의 fault/restart 통합 검사와 이 검토는 독립적이다. 합성 검사 결과와 관계없이 실제 운영 증거와 합성 회귀 결과를 구분해야 하며, a407의 누락 자료나 독립 종료 증거를 보충한 것으로 해석할 수 없다.

[실거래 준비 현황](LIVE_READINESS.md)의 기존 예약 검토, 실제 시세 Paper 주문/체결 경로, 운영 회복 검증은 별도 완료 기준이다. 기록된 실제 KR/US 유한 Paper 60 tick·의도/체결 0건은 매수→매도·비용·원가 경로 검증 완료가 아니다. MA 5/20은 시스템 검증용이고 실거래 전략은 확정되지 않았다. 정책 검토 문서 작성이나 향후 fencing 검증도 이 미검증 범위를 닫지 않으며, live 거부·실주문 API 미구현 경계를 유지한다.

## 실제 결정해야 할 사항 하나와 현행 근거

**결정 사항: 과거 독립 종료 자료만 허용하는 현재 조건을 유지할지, 아니면 구실행 권한의 실제 폐기를 독립적으로 검증하는 새 정책안을 별도 설계할지다.** 후자는 현재 종료 증거를 확보했다고 간주하는 예외가 아니다. 새 안전 근거·수용 기준·변경할 지침을 구체화하고 사용자가 별도로 정책 변경을 승인해야 구현/적용을 검토할 수 있다. 이번 문서는 정책 변경이나 적용을 하지 않는다. 단순 root/DB 이동·시간 경과·수동 확인서만의 해제는 대안에 포함하지 않는다.

현행 인용 근거:

> 원본 파일 집합/바이트 hash와 직접 소유한 프로세스의 독립 launch/exit를 검증한 별도 처리 기록만 허용한다.

> 현재 계좌 정지·인증 잠금 획득·기한 경과·종료 파일의 자기 보고는 이 근거를 대체하지 않는다.
