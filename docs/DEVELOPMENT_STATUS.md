# 개발·운영 검증 현황

상세는 [오프라인 준비 기록](PAPER_OFFLINE_PREPARATION.md)을 따른다. 현재 웹/API는 localhost 5173/4000의 기존 개발 프로세스이고, Docker에는 기존 업무 DB 5432·합성 Paper DB 59257와 새 실제 시세 Paper DB 55434를 유지한다. 검증 전용 임시 DB/복원 복사본은 정리했다. 새 계좌를 현재 웹에 자동 연결하거나 worker를 시작하지 않았다. 이 개발용 DB 분리는 향후 운영 Compose의 컨테이너 수를 늘리는 요구가 아니다.

## 실제 증거가 필요한 다음 작업

1. 미국 `us-2026-10-30-retry-1` 최종 리포트와 journal의 hash·합계·간격·세션·지연·오류를 검토한다. 예약 대기/프로세스 생존/절전 방지 활성은 완료 증거가 아니다.
2. 국내 60회 결과는 수집 정상 60/60이지만 절전 공백 2건이 있어 연속성 통과로 채택하지 않는다. 다음 확인된 정규장에서 필요한 연속 수집 증거를 보강한다. 현재 문서로 다음 영업일을 추정하거나 새 관측을 자동 예약하지 않았다.
3. 세션/거래일 경계·실제 수집 중 취소/정리·장시간 토큰 갱신의 부족한 증거를 따로 확인한다. 미국 결과만으로 국내나 다른 수명 검증을 통과시키지 않는다.
4. 검토한 시장의 준비 계좌를 다시 점검하고 기존 토큰 소유자 정리 후 실제 시세를 정지 상태로 1회 관측한다. 설정 hash·출처·보유분·데이터 신선도·일일 기준을 확인한다. 준비 계좌에 `--initialize`를 반복하지 않는다.
5. 필요한 일일 손실 검토와 별도 명시적 재개를 거쳐 첫 Paper 실행을 유한 60 tick으로 제한한다. 종료 후 정지/lease·미체결 정리·현금/수량·비용/원가·중복 의도·진단/자산 이력을 검토한다. 신호나 체결이 없으면 해당 경로는 미검증으로 남긴다.

실주문·외부 배포·실운용 전략/자금 결정은 별도 범위다. 초기 준비 일치와 실제 수익성·거래 권한을 연결하지 않는다. 자동 재개·자동 한도 상향·기존 손실 초기화는 제공하지 않는다.
