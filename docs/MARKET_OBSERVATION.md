# 읽기 전용 시세 관측과 운영 리포트

## 범위

`market:observe`는 실제 시세를 반복 조회해 데이터 품질과 수집 오류를 기록하는 유한 실행 명령이다. 백테스트나 Paper worker를 실행하지 않는다. 기본 관측 경로는 계좌·잔고·매수 가능 금액을 조회하거나 Paper 계좌 생성·전략 평가·주문 의도·예약·체결·재개·일일 기준 승인을 수행하지 않는다. DB는 기존 토큰 발급 advisory lock에만 사용하며 업무 데이터를 저장하거나 마이그레이션하지 않는다. 인프라·배포 설정을 바꾸지 않았다. 새 의존성은 없다.

시장 검사 `assessMarketData`는 기존 `prepareStrategyData`의 시장 검증을 공유하되 계좌를 검증했다고 가정하지 않는다. 기존 전략 검사는 계좌 상태/신선도도 계속 요구한다. 리포트의 `assessmentScope=market-data-only`와 `executionEnabled=false`를 유지한다. 정상 관측도 전략 warmup·계좌·리스크·실행 권한 검증을 뜻하지 않는다.

## 실행

저장소 루트에서 실행한다. 합성 데모는 키·DB·토스 연결이 필요 없고 현재 KR만 지원한다.

```bash
corepack pnpm market:observe --demo
# 여러 관측의 파일 저장/간격을 점검하는 합성 예시
corepack pnpm market:observe --demo --samples=3 --interval-seconds=10
```

실제 관측은 기존 서버 `.env`의 TOSS_CLIENT_ID/TOSS_CLIENT_SECRET/DATABASE_URL과 허용 IP 설정을 사용한다. 키를 명령 인자나 채팅에 넣지 않는다. DB는 다른 조회 명령과 동일한 토큰 잠금 DB여야 한다. READONLY_SYMBOLS는 기본 KR:005930,US:AAPL이며 `--symbols`로 관측 종목만 지정할 수 있다.

```bash
# 기본 1회. 주문/Paper 계좌 없이 KR/US 시세만 확인
corepack pnpm market:observe --symbols=KR:005930,US:AAPL

# 완료 후 60초 간격으로 480회. 수집 시간을 포함하므로 정확히 8시간은 아니다.
corepack pnpm market:observe --symbols=KR:005930,US:AAPL --samples=480 --interval-seconds=60
```

기본은 samples=1, 관측 완료 후 간격 60초, 프레임 수집 대기 한도 10초다. 최대 5종목·1분봉·종목당 1페이지(최대 200봉)만 사용한다. CANDLE_INTERVAL=1d 또는 CANDLE_MAX_PAGES가 1이 아닌 설정은 무시하지 않고 거부한다. samples는 1–10,000, 간격은 10–3,600초다. --resume/실주문 모드는 없다. 컴퓨터와 터미널이 실행 중이어야 관측이 진행된다.

### 정규장 1회 예약

`--regular-only`는 실제 시세의 단일 시장만 허용한다. 시작 직전 같은 토큰 잠금 안에서 캘린더를 다시 조회하고, 현재 정규장에 남은 시간이 요청한 수집 예산(모든 프레임 timeout + 관측 사이 간격)보다 길어야 시작한다. 휴장·미확인 세션·다른 시장·남은 시간 부족은 `OBSERVATION_SESSION_UNAVAILABLE`로 종료한다. 횟수 완료를 데이터 정상 승인으로 해석하지 않는다.

```bash
# 토스 캘린더로 확인한 UTC 시각을 명시한다. 예시는 2026-10-29 미국 정규장이다.
corepack pnpm market:observe --symbols=US:AAPL --samples=60 --interval-seconds=60 --regular-only --start-at=2026-10-29T13:35:00Z
```

`--start-at`은 `--regular-only`와 함께만 사용하며 최대 36시간 뒤까지 기다린다. 대기 중에는 DB 연결·토큰 발급·잠금·관측 파일을 만들지 않는다. 30초 이하 간격으로 시각과 취소를 확인하며 시작을 2분 넘게 놓치면 `OBSERVATION_START_MISSED`로 종료한다. 절전 해제 후 잘못된 세션을 대신 수집하지 않는다. SIGINT/SIGTERM은 대기를 취소한다. 반복 일정·자동 재시작·절전 해제 기능은 없다.

백그라운드로 실행할 때도 PC와 DB가 관측 시간에 실행 중이어야 한다. 예약 대기는 로그의 `waiting`과 [예약 기록 화면](OBSERVATION_JOBS.md)에서 확인한다. 실제 수집 리포트는 시작 후 생성된다. 실패 시 자동 재시도하지 않는다. 시작 시 같은 client의 다른 수집이 잠금을 보유하면 기존 `BROKER_LEASE_BUSY` 정책으로 종료한다. 실제 수집 동안에는 기존 timeout·취소·오류 중단 정책을 유지한다.

## 토큰과 수명

실제 관측은 전체 실행 동안 같은 client hash/같은 DB의 기존 advisory lock을 보유한다. broker와 메모리 토큰은 한 실행에서 공유한다. API 새로고침·broker:check·Paper 실제 시세 CLI가 같은 client로 동시에 토큰을 발급하지 못하며 나중 요청은 BROKER_LEASE_BUSY로 실패할 수 있다. 웹의 메모리/DB 캐시 조회는 별개다. 다른 DB/외부 스크립트의 발급까지 이 잠금으로 막지는 못한다.

관측은 겹치지 않으며 완료/기록 후 간격을 기다린다. 수집은 기존 adapter의 rate limit/재시도 정책을 따른다. 일시적인 수집 실패는 기록하고 다음 간격에 다시 관측하되 연속 3회면 종료한다. 인증·권한·잘못된 응답·미지원 시장은 즉시 종료한다. 관측 프레임 timeout도 즉시 통신 수명 signal을 취소하고 종료한다. timeout 이후 다음 관측을 시작하지 않는다.

진행 중 broker 요청/재시도 대기 정리가 끝나야 토큰 잠금을 해제한다. 따라서 10초는 수집 결과를 기다리는 한도이며 종료 정리까지 반드시 10초에 끝난다는 뜻은 아니다. SIGINT/SIGTERM도 통신 취소·정리 후 종료하며 SIGKILL/전원 종료에는 완료 리포트를 보장하지 않는다.

## 관측 결과

각 종목에 정상(healthy)·확인된 정규장 밖/휴장(closed)·차단(blocked)을 기록한다. 휴장이어도 시세 시각 누락·오래된 캔들·환율 만료 등의 사유를 제거하지 않는다. 캘린더 미확인/만료는 정상 휴장으로 취급하지 않는다. quote 시각이 이전 최댓값보다 뒤로 가면 차단하며 회복 여부를 이후 관측에서도 비교한다.

기록에는 시작/종료·수집 소요 시간, 종목, 시세 시각/지연, 최신 봉 시각, 종료/대기/제외 봉 수, 차단 사유만 남긴다. 가격·OHLCV 원본·계좌·원본 API 응답·인증 정보는 저장하지 않는다. 실제 체결가의 수신 시각은 시장 상황에 따라 오래될 수 있으므로 데이터 차단 수를 곧바로 장애율로 해석하지 않는다. 종목/세션별 원인과 함께 검토한다.

종목별 카운터는 수집에 성공한 종목 관측을 센다. 수집 오류 횟수는 프레임 단위이며 별도로 표시한다. completed는 요청한 반복을 마쳤다는 뜻이다. 차단이나 일시 오류가 있어도 completed일 수 있으며 자동 운용 합격 판정은 없다. failed는 조기 중단, cancelled는 취소다.

## 파일과 보존

기본 경로는 실행 위치와 관계없이 저장소의 `.local-data/observations/<runId>/`다. 상대 --output 경로도 저장소 루트를 기준으로 해석하며 절대 경로도 허용한다. 각 실행은 별도 UUID 디렉터리를 생성하므로 기존 결과를 덮어쓰지 않는다. 디렉터리는 0700, 파일은 0600으로 생성한다. 기존 상위 디렉터리 권한을 임의로 변경하지 않는다.

| 파일          | 내용                                                                              |
| ------------- | --------------------------------------------------------------------------------- |
| manifest.json | 출처·정책 버전·관측 범위/횟수/간격, 시작 시각                                     |
| samples.jsonl | 관측마다 검증 후 append·sync하는 제한된 메타데이터                                |
| summary.json  | 실행 종료 상태, 전역/종목별 카운터와 지연·오류, journal SHA-256                   |
| report.md     | 사람이 읽는 요약과 종목/차단/오류 표                                              |
| failure.json  | 잠금 상실·상위 실행 실패 등으로 정상 요약을 반환하지 못한 경우의 제한된 오류 코드 |

summary/failure JSON은 임시 파일을 쓴 뒤 rename한다. SHA-256은 저장된 journal의 변경 확인용이며 시세 진위/시점 공증이 아니다. 파일 쓰기가 실패하면 수집을 중단한다. 저장 장치 장애나 강제 종료로 최종 파일이 없을 수 있으며 manifest/journal만 있으면 미완료 실행으로 다룬다. 원본 오류 문자열 대신 허용된 코드만 기록한다. 기존 리포트를 읽는 동작으로 관측이나 거래를 재실행하지 않는다. .local-data는 Git에서 제외한다.

## 검증과 다음 단계

fixture 테스트로 시장 검사/계좌 검사의 분리, 휴장·불명확 캘린더, 시각 퇴행, 오류 후 회복/연속 중단, 인증 차단, timeout 취소/정리, 저장 실패, 출처/종목 혼입을 검증한다. 파일 테스트는 권한·journal hash·완료/실패/미완료 구분과 비공개 필드 제외를 확인한다. 일반 테스트는 실제 증권사 API를 호출하지 않는다.

합성/짧은 실제 관측은 장기간 운용 검증이 아니다. 이후 KR/US 정규장·휴장·거래일 경계를 포함한 관측 리포트를 축적하고, 데이터 지연/결측을 검토한 뒤 별도의 Paper 운용 검증으로 진행한다. 운영 리포트 대시보드는 구현했다. 자동 스케줄러·실주문·외부 배포는 후속이다. [실제 운영 검증 목록과 증거](OPERATIONAL_VALIDATION.md)를 따른다.

구현 후 수동 검증에서 키/DB 없는 합성 CLI 2회 수집과 journal 해시를 확인했다. 기존 승인된 읽기 전용 설정으로 KR:005930/US:AAPL을 1회 관측했고 수집 오류 0, 국내 정상 1/미국 정규장 밖 1로 기록했다. 미국 시세 지연·종료 봉 부족 사유도 보존했다. 계좌·주문 API나 Paper 원장은 사용하지 않았다. 이는 단발 연결 확인이며 장시간/전체 시장 세션 검증을 완료한 것은 아니다.

## 대시보드 조회

소유자 로그인 후 `http://127.0.0.1:5173/#observations` 또는 **시세 관측** 메뉴에서 저장된 실행을 선택한다. 합성/실제 시세 출처, 관측 대상, 시작/종료, 실행 상태, 종목별 품질·오류, 최근 최대 50회 기록을 확인한다. 관측 종료와 데이터 정상 여부는 별도로 표시한다. 최종 요약이 없는 항목은 **진행 중 또는 미완료**로 표시하며 진행 중임을 확정하거나 정상 완료로 간주하지 않는다. 미완료 journal은 완성된 줄의 schema·순서·종목 집합을 검증한 뒤 최종 해시 검증 전의 임시 기록으로 표시한다. 완료 요약이나 정상 실행으로 승격하지 않는다.

- `GET /v1/observations`: 서버 고정 `.local-data/observations` 폴더의 검증된 목록
- `GET /v1/observations/:id`: UUID로 선택한 실행의 검증된 상세

두 API는 소유자 세션과 기존 localhost/Host/Origin 경계를 요구하고 no-store/private로 응답한다. 브라우저의 경로·계좌·수집 시작 옵션과 query parameter는 받지 않는다. 파일 변경·삭제 또는 검증 실패 시 상세를 다시 읽지 못한 것으로 표시한다. 새로고침은 파일 조회만 수행하며 시세 수집/거래/worker 실행을 시작하지 않는다. 외부 배포에는 연결하지 않았다.

공통 Zod 계약으로 manifest/terminal/journal의 비공개 추가 필드·형식·ID·종목 집합을 검사하고, journal SHA-256과 연속 순서를 검증한다. 정상 종료 요약은 journal에서 다시 집계한 카운터/지연/오류와 일치해야 한다. failure.json도 해시를 검사하며 요약 없음 상태를 유지한다. 저장된 Markdown은 읽거나 HTML로 렌더링하지 않는다.

심볼릭 링크·일반 파일이 아닌 항목·경로 이탈을 거부한다. manifest는 8KiB, terminal은 256KiB, journal은 32MiB를 상한으로 읽는다. 목록은 디렉터리 후보 100개·리포트 50개·실제 읽기 총량 64MiB로 제한하고 실패한 파일의 읽기도 용량에 포함한다. 제한/검증 제외 수를 표시하며, 목록은 스캔 범위 내에서 시작 시각순으로 정렬한다. 상한 도달 시 전체 디렉터리의 최신 50개를 보장하지 않는다. 목록 캐시는 5초이고 상세는 매번 재검증한다. 이는 로컬 OS 사용자 신뢰 경계이며 해시가 시세 원천의 진위를 증명하는 것은 아니다.

## 관측 중 웹 계좌 조회

새 실행에 `--share-dashboard`를 지정하면 잠금 owner의 broker를 웹 계좌 조회와 공유한다. 관측 자체의 평가/리포트 범위는 시장 데이터만 유지하며, 명시적인 웹 새로고침은 계좌·보유분 조회를 추가할 수 있다. 공유하지 않는 실행은 기존 잠금 제한을 유지한다. 토큰을 전달하지 않으며 [공유 조회 정책](SHARED_DASHBOARD.md)의 취소·정리·로컬 권한 경계를 따른다.

## 기록 갱신·수집 공백 감지

API는 저장된 journal을 읽어 마지막 저장/수집 성공 시각, 갱신 기한, 수집 사이 공백을 계산한다. 파일 수정 시각·PID 생존·예약 대기 로그로 정상 수집 중이라고 추정하지 않는다. 시세 품질 정상과 수집 연속성도 별개다. 새 worker·DB·서비스·외부 통신 없이 기존 리포트 형식에 대한 읽기 전용 계산으로 동작한다.

- 추가 지연 허용치는 `max(30초, 설정 간격)`이다. 다음 기록 기한은 `마지막 기록 종료 + 설정 간격 + 수집 timeout + 추가 지연 허용치`다. 첫 기록 대기와 모든 샘플 저장 후 종료 요약 대기는 설정 간격을 더하지 않는다. 기한을 **넘으면** `overdue`, 기한 안의 최근 기록은 `recent`, 요청 수를 채운 미완료 실행은 `awaiting-finalization`이다.
- 이전 수집 종료부터 다음 수집 시작까지의 대기에서 설정 간격을 뺀 값이 추가 지연 허용치를 넘으면 수집 공백으로 센다. 전체 공백 수/최대 대기·초과 시간을 계산하고 최근 공백 10건을 표시한다. 종료 기록은 시간이 지나도 실행 중 지연으로 바꾸지 않으며 공백을 보존한다.
- 시각 역행·미래 기록은 `clock-unverified`로 표시한다. 기록은 있는데 마지막 수집 성공이 오래된 경우 두 시각을 따로 보여준다. 성공은 수집 요청 성공이며 시장 품질이나 매매 가능을 의미하지 않는다.
- 미완료 journal은 최종 hash 없이 `provisional`로 표시한다. 완성된 newline 줄만 읽고 마지막 미완성 줄은 제외한다. 미완성 꼬리 8KiB, journal 32MiB, 목록 전체 64MiB/100후보/50결과 상한과 NOFOLLOW·고정 UUID·canonical root 검사는 유지한다. 변조된 완성 줄은 누락시키지 않고 해당 리포트를 거부한다. 최종 리포트는 기존 전체 hash·집계 검증 후 `final-hash-verified`로 표시한다. 미완료 기록을 읽은 직후 종료 파일이 생기면 다음 조회에서 검증한다.
- 화면은 저장 기록을 10초마다 조회한다. 목록 캐시는 최대 5초이며 판정 시각을 함께 표시한다. 조회 실패 시 현재 상세를 숨기며 이전 결과를 정상 상태로 유지하지 않는다. 조회로 수집·토큰 발급·Paper 재개를 실행하지 않는다.

이 감지는 원인을 자동 확정하거나 운영체제 절전을 막지 않는다. PC/API가 잠들거나 브라우저가 중단되면 그동안 화면 경고도 갱신할 수 없다. 깨어난 뒤 공백이 드러나며, 외부 상시 감시·알림은 후속 범위다. OS 시각 점프도 기록 시각만으로 절전과 완전히 구분할 수 없다.

로컬 macOS에서 장시간 수동 관측을 실행할 때 필요하면 `caffeinate -i corepack pnpm market:observe ...`로 해당 명령이 실행되는 동안 유휴 절전을 방지할 수 있다. 이 문서의 예시는 자동 실행하지 않았으며 기존 예약/프로세스·OS 전원 설정도 변경하지 않았다. 명령은 화면 꺼짐과 별개이며 덮개 닫기·수동 절전·전원 차단까지 방지한다고 보장하지 않는다. 다른 OS의 상시 운영 절전 정책은 별도 설정한다.
