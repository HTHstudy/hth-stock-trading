# 이동평균 교차와 백테스트 MVP

## 실행

키·DB·네트워크 없이 합성 데이터로 확인할 수 있다. 아래 경로 인자는 worker 디렉터리 기준이다. `--output`을 생략하면 요약만 출력한다.

```bash
corepack pnpm backtest:run --demo --config=../../examples/backtest-config.json --output=../../.local-data/backtest-demo.json
```

`examples/backtest-config.json`의 가격·기간·원금·수수료·세금·슬리피지는 **기능 검증용 가정**이다. 현재 증권사 요율·법정 세율·투자 권장값이 아니다. 실제 과거 시점과 계좌에 맞는 실험 설정은 별도로 입력해야 한다. 결과를 실제 전략 성과로 해석하지 않는다.

실제 동결 데이터는 [데이터셋 export](HISTORICAL_DATASETS.md)를 입력하거나 DB의 ID로 읽을 수 있다. 원본 artifact는 변경하지 않는다. `--demo`, `--input`, `--dataset` 중 정확히 하나만 지정한다.

```bash
corepack pnpm backtest:run --input=../../.local-data/dataset.json --config=../../examples/backtest-config.json --output=../../.local-data/backtest.json
corepack pnpm backtest:run --dataset=<UUID> --config=../../examples/backtest-config.json --output=../../.local-data/backtest.json
```

파일 입력은 schema와 SHA-256을, DB 입력은 저장소의 schema와 SHA-256을 확인한다. 엔진은 원본 관측·캘린더에서 데이터셋을 재생성해 선택 봉·종료 증거·커버리지도 다시 대조한다. 미완성·누락·변조·0 이하 가격은 거부한다. 파일 입력 최대 64 MiB, 설정 최대 1 MiB다.

저장 파일은 신규 JSON만 생성하며 기존 파일은 덮어쓰지 않는다. 같은 경로로 재실행하면 `BACKTEST_REPORT_EXISTS`로 실패하므로 다른 경로를 지정하거나 `--output`을 생략한다. 신규 디렉터리는 0700, 파일은 0600이고 `.local-data/`는 gitignore 대상이다. `paper`만 허용하며 증권사 호출·주문·DB 변경은 수행하지 않는다. DB 모드만 DB 연결이 필요하다.

## 전략 계약

`Strategy<Config>`는 id·version과 순수 `evaluate(context, config)`를 제공한다. broker·DB·시스템 현재 시각을 참조하지 않는다. 현재 시각은 context의 `evaluatedAt`이며, 자동 소유 수량과 종료된 봉 prefix를 받는다. 신호는 BUY·SELL·HOLD이고 주문 크기는 엔진의 별도 정책이다.

`moving-average-cross@1.0.0`은 직전 봉과 현재 봉의 단순 이동평균을 비교한다. fastPeriod와 slowPeriod는 정수이며 `1 ≤ fast < slow ≤ 2000`이다. 직전 평균까지 필요하므로 최소 `slow+1`개 봉을 요구한다. 부족하면 WARMUP/HOLD다. 이전 fast ≤ slow에서 현재 fast > slow가 되면 BUY, 반대는 SELL, 같거나 교차가 없으면 HOLD다. 포지션 유무로 신호를 숨기지 않고 엔진이 중복 매수·공매도를 차단한다.

십진 종가를 공통 소수 자릿수로 맞춘 BigInt 합과 교차 곱으로 비교한다. 평균 나눗셈이나 부동소수점 오차를 사용하지 않는다. 전략 교체는 이 인터페이스를 구현하면 되며 엔진·비용 로직을 변경하지 않는다. 현재 CLI는 이 검증용 전략 하나를 연결한다.

## 체결 시간과 미래 데이터 참조 방지

모델은 `next-eligible-open-v1`이다. 각 봉의 시가·종가·종료 증거에 따른 신호 가능 시각을 정렬해 처리한다. 분봉 시작은 종료 timestamp-1분, 일봉 시작은 정규장 시작이며 종가 평가 지점은 보수적으로 제공 세션 전체 종료다. 일봉의 현지 자정 timestamp를 시가 시각으로 사용하지 않는다.

**국내 일봉에 정규장 외 세션이 포함되면 `UNSUPPORTED_KR_DAILY_SESSION`으로 차단한다.** 공식 FAQ에서 국내 종가는 KRX·NXT 통합 마지막 체결가이며, 해당 일봉 시가를 정규장 시가로 확정할 증거가 부족하다. 이를 정규장 가격으로 추측해 체결하지 않는다. 국내는 정규장 분봉 또는 정규장만으로 구성된 검증 입력을 사용하고, 미국 일봉은 공식적으로 정규장 OHLC이므로 지원한다. 합성 데모의 국내 일봉은 정규장만 포함한다. 실제 국내 통합 일봉의 체결 지원에는 세션과 일치하는 가격 입력을 추가해야 한다. [공식 FAQ](https://openapi.tossinvest.com/openapi-docs/faq.md)

- 전략에는 해당 봉까지의 불변 prefix만 전달한다. 미래 봉과 전체 데이터셋은 전달하지 않는다. 전략 설정도 복제해 동결한다. 플러그인은 순수 함수 계약을 지켜야 하며 임의 코드의 I/O를 차단하는 sandbox는 아니다.
- 신호는 원본 봉의 `usableAt`에서 평가한다. 이것은 재수집 대기 정책으로 계산한 모델상 정보 가용 시각이며, 현재 수행한 실제 수집 시각을 과거 시점으로 간주하지 않는다.
- 체결은 원본 봉 이후의 봉이면서 시가 시각이 신호 평가 시각 이상인 첫 봉이다. 같은 시각이면 종료 평가 → 신호 → 다음 시가 순서다. 일봉은 보통 다음 거래일, 분봉은 60초 대기 때문에 통상 두 봉 뒤 시가가 된다. 마지막 국내 마감 분봉은 보수적인 16:01 이후 정책을 따른다.
- 같은 봉 종가 체결, 마지막 봉 이후의 가상 봉 생성, 암묵적인 종료 청산은 없다. 남은 의도는 UNFILLED_END로 기록한다.
- 대기 중 HOLD는 기존 의도를 유지한다. 같은 방향은 PENDING_EXISTS, 반대 신호는 이전 의도를 SUPERSEDED로 바꾸고 현재 포지션에 따라 새 신호를 검사한다.

이벤트 시간 모델은 미래 봉을 전략에 넘기는 오류를 막는다. 원천 데이터는 사후 수집본이므로 당시 확정 정보만을 보장하지 않으며 `pointInTime=false`다. 사후 조정·상폐 누락·미국 일부 거래소 데이터 제약은 그대로 남는다.

## 자금과 비용 가정

한 종목·한 통화의 현금 계정, 무차입 long-only다. 초기 포지션은 0이고 소수 주식·추가 매수는 지원하지 않는다. BUY는 설정된 정수 quantity, SELL은 전략이 보유한 전체 수량이다. 현금 부족·이미 보유 중인 매수·수량 없는 매도는 기록하고 체결하지 않는다. 실패한 의도는 자동 재시도하지 않는다. 실제 장기 보유 계좌를 가져오거나 매도하지 않는다.

모든 비용 설정을 명시한다. Bps는 1/10000 단위이며 각 비율은 0 이상 10000 미만, 매도 수수료+세금 비율도 10000 미만이어야 한다. 원금·quantity·priceTick은 양수이고 초기 현금은 KRW 1원·USD 0.01 단위다. MVP의 고정 priceTick은 최소 해당 통화 단위와 그 배수로 제한한다.

1. 매수 가격 = 시가 × (1 + slippageBps/10000), 매도는 (1 - slippageBps/10000).
2. 매수 가격은 고정 priceTick으로 올림하고 매도는 내림한다. 0 이하 체결 가격은 거부한다.
3. 수수료와 매도세는 체결대금 × 각 bps이며 KRW 1원·USD 0.01 단위로 각각 올림한다. 실제 증권사 절사·최소수수료 규칙을 복제한 것이 아니다.
4. 매수 시 대금+수수료를 차감하고 매도 시 대금-수수료-세금을 더한다. 차입이 필요하면 체결하지 않는다.

금액 계산에는 worker가 이미 사용하던 `decimal.js@10.6.0`을 trading에서도 재사용한다. BigInt 고정 소수점만으로 비율·반올림을 별도 구현하는 비용을 줄이며 새 라이브러리 종류는 도입하지 않았다. 독립 clone의 정밀도 100자리로 전역 설정 영향을 피한다. [공식 API와 반올림 명세](https://mikemcl.github.io/decimal.js/)를 확인했다. 원금·수량·가격·비용은 JSON에서 십진 문자열이고 비율 출력은 소수 10자리다.

체결은 유동성·거래량·호가 잔량·거래 정지·상하한가·실제 시장가 주문 조건을 검증하지 않는 합성 전량 체결이다. 슬리피지 적용 가격은 봉의 고가·저가 바깥일 수 있다. 거래량을 미래 신호에 사용하거나 무체결 구간을 임의로 생성하지 않는다. 실제 호가 단위는 시점·가격대·시장별로 달라 고정 tick이 충분하지 않으며, 실제 Paper/Live 실행 전에 별도로 구현해야 한다.

## 결과와 지표

artifact에는 입력 데이터셋 ID/hash/출처, 엔진·전략 버전, 전략 파라미터, 비용 설정, 체결 모델, 신호 상태, 체결·왕복 거래, 자산 곡선과 한계가 포함된다. SHA-256은 `reportHash` 필드만 제외한 전체 artifact를 기존 `contentHash` 함수로 계산한다. 실행 현재 시각과 난수를 포함하지 않아 같은 입력·버전이면 같은 hash다. 합성 입력은 `synthetic-demo-v1`으로 구분한다.

- netPnl = 최종 현금 + 미청산 수량 × 마지막 종가 - 초기 현금.
- realizedPnl은 완료한 왕복 거래의 매도 순대금-매수 원가이며 양방향 수수료와 세금을 포함한다. unrealizedPnl은 마지막 종가 평가액-남은 매수 원가다.
- cumulativeReturnPct = netPnl/초기 현금 × 100. 자산 곡선 각 시점에도 같은 방식으로 누적 수익률을 기록한다.
- MDD는 초기 자산과 각 시가·종가 평가 지점의 누적 고점 대비 하락률 최댓값이다. 봉 내부의 저점·체결 순서를 재현한 MDD가 아니다.
- winRatePct는 청산 완료 거래 중 비용 차감 순손익 > 0인 비율이다. 손익 0은 승리가 아니고 완료 거래가 없으면 null이다.
- tradeCount는 완료 왕복 거래 수, fillCount는 매수·매도 체결 수다. 미청산 포지션은 거래 수·승률에서 제외한다.

초기 현금 0은 거부해 수익률 분모를 보장한다. 환전·배당·분할에 따른 보유 수량 및 현금 조정, 기간별 비용 변화, 멀티 종목 포트폴리오와 실제 주문 원장은 아직 없다. adjusted 가격을 쓰더라도 배당 총수익이나 실제 당시 체결가를 보장하지 않는다.

## 로컬 조회·비교 화면

`corepack pnpm dev` 실행 후 [백테스트 실험실](http://localhost:5173/#backtests)에서 `.local-data` 바로 아래에 저장한 JSON 리포트를 조회한다. 키·DB 없이 동작하고 실험 실행이나 주문 API는 제공하지 않는다. 비교용 합성 설정도 제공하며 파라미터와 비용은 기능 검증용 가정이다.

```bash
corepack pnpm backtest:run --demo --config=../../examples/backtest-compare-config.json --output=../../.local-data/backtest-demo-compare.json
```

기준·비교 리포트 선택, 손익·수익률·MDD·승률, 조건과 비용 비교, 종료 보유 수량, 체결·왕복 거래·신호 내역과 50개씩 페이지 이동을 제공한다. 합성 데이터를 파일로 다시 입력해도 합성 데모로 표시한다. 곡선은 같은 데이터셋 hash·통화·초기 자산일 때만 겹치며 수량·비용 차이는 표에 표시한다. 수익률 합산·자동 순위는 없다. 비교 선은 보라색 점선, 기준 선은 청록색 실선이다. 같은 시각은 마지막 평가값을 쓰고 좌표만 number로 변환한다. 정확한 금액·비율은 문자열로 표시한다. 차트 시간축은 UTC, 내역은 한국 시간이다.

API는 `GET /v1/backtests`와 `GET /v1/backtests/:hash`다. 개발용 loopback 서버에서만 저장소를 구성하고 production·public bind에서는 비활성화한다. 기존 localhost IP·Host·Origin·cross-site 차단과 no-store 정책을 적용한다. Vercel 공개 SPA는 로컬 리포트에 접근하지 않으며 외부 배포용 인증은 후속이다.

`backtest-artifact-v1`과 engine·이동평균 전략 `1.0.0`의 schema·참조 인덱스·건수 및 SHA-256을 검증한다. 중복 hash는 하나만, 검증 실패와 다른 JSON은 제외 개수만 표시한다. 파일명·절대 경로·원본 실패 내용은 반환하거나 로그에 남기지 않는다. 파일·디렉터리 symlink는 거부하며 브라우저에서 경로를 지정할 수 없다.

scan은 항목 최대 100개·파일 32 MiB·누적 읽기 64 MiB로 제한하고 상한 도달을 알린다. 목록은 hash순이고 색인은 최대 5초 보관한다. 새 파일은 최대 5초 후 목록 새로고침으로 반영된다. 상세 조회는 파일을 다시 검증하므로 변경·삭제한 파일을 기존 hash로 반환하지 않는다. 검색·날짜 정렬·리포트 DB 색인은 후속이다.

hash 검증은 내용 일치 확인이며 과거 데이터 재수집·전략 재실행·성과 재계산·작성자 인증이 아니다. 로컬 파일과 hash를 함께 바꾼 작성자를 판별하지 않는다. 재현 실행에는 원본 동결 데이터셋과 CLI를 사용한다. API는 기존 `@hth/database`의 순수 hash 함수를 재사용하되 리포트 조회에서 DB를 연결하지 않는다. 새 외부 라이브러리는 도입하지 않았다.

테스트는 생성한 가짜 파일을 사용하고 ignored `.local-data`의 존재를 요구하지 않는다. Chrome에서 기본 화면의 지표·표·차트 영역 표시를 확인했다. 비교 메뉴 자동 조작은 브라우저 제어가 간헐적으로 중단되어 끝까지 검증하지 못했다.

## 검증과 다음 단계

교차·동일 평균·warm-up, 안전 정수 범위를 넘는 가격, 신호 prefix 불변성, 미래 값 변경, 다음 시가·세션/대기 시각, 비용 반올림, 무거래·현금 부족·미청산·손익·승률·MDD, 데이터셋 변조와 결과 hash를 테스트한다. 테스트는 실제 증권사 API나 실제 계좌를 사용하지 않는다.

로컬 조회·비교 화면까지 구현했다. 다음은 검토한 마이그레이션의 명시적 적용과 실제 동결 입력 확보, 여러 기간의 실험 검증이다. 이후 Phase 3에서 리스크 한도·긴급 정지·소유권·주문 의도 원장과 자체 Paper 체결을 구축한다. 이 엔진만으로 자동매매를 시작하지 않는다.
