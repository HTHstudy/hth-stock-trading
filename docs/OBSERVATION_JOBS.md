# 정규장 관측 예약 기록 조회

## 화면과 해석

소유자 로그인 후 **시세 관측** 화면 위쪽에서 시작 전 기록, 시작 시각 경과·결과 미확인, 실패·취소·로그상 완료를 확인한다. 10초마다 파일을 다시 읽으며 조회 실패 시 이전 값을 현재 상태로 표시하지 않는다.

예약 기록은 프로세스 생존 증명이 아니다. 시작 시각이 지났는데 종료 로그가 없으면 실행 중인지 중단됐는지 추정하지 않는다. `OBSERVATION_START_MISSED`가 명시적으로 기록된 경우에만 시작 누락 실패로 표시한다. 절전 등 원인이 로그에 없다면 원인을 확정하지 않는다.

완료도 **로그상 완료**이며 데이터 정상이나 운용 승인과 다르다. 결과 ID가 현재 리포트 목록에 있으면 해당 리포트를 선택한다. 상세 조회에서 기존 schema·journal hash·집계를 별도로 검사한다. 목록에 없으면 새로고침을 안내하고 다른 리포트로 연결하지 않는다. 부분 관측 journal은 이 API로 노출하지 않는다.

## 저장소와 API

`GET /v1/observations/jobs`는 기존 소유자 인증·localhost·Host/Origin·no-store/private 경계를 사용한다. query와 사용자 경로는 받지 않는다. 서버 고정 `.local-data/scheduled-observations`에서 `kr|us-YYYY-MM-DD` 또는 `-retry-N`(1–99)을 붙인 디렉터리만 읽는다. 재시도는 이전 실패를 덮어쓰지 않는 별도 기록이다.

`launch.json`의 이름·PID·시각·단일 시장 종목·횟수·간격·실행 비활성·스크립트 hash를 strict schema로 검사한다. 예정 시각은 시작 기록의 36시간 이내이며 2분보다 오래된 예정 시각으로 시작한 기록은 거부한다. PID/hash 형식 검사는 실제 프로세스·파일의 진위 확인이 아니다. `process.log`는 기존 runner의 대기 1줄과 선택적 종료 1줄만 허용한다. 시각·상태·허용된 코드·출처·횟수를 검증하며 정상 완료는 요청 횟수와 같아야 한다.

임의 오류 원문·비공개 추가 필드·부분 JSON·불일치는 제외한다. PID·경로·hash·계좌·인증·원본 로그는 응답하지 않는다. 루트/디렉터리/파일 심볼릭 링크와 일반 파일이 아닌 대상도 거부한다. launch 4KiB, 로그 8KiB, 총 읽기 512KiB, 탐색 100개/반환 20개 상한을 둔다. 반환 기록은 예정 시각 내림차순이며 제한 시 전역 최신 20개를 보장하지 않는다. 검증 제외 수와 상한 도달을 표시한다. 없는 루트는 빈 목록, 잘못된 루트·저장소 오류는 상세 원문 없이 503이다. 부분 쓰기는 다음 조회에서 다시 검증한다.

조회로 파일 변경·signal 전송·예약 생성·취소·재실행·토큰 발급·시세 수집·Paper 재개를 수행하지 않는다. DB 마이그레이션·새 의존성·OS 스케줄러·외부 배포는 추가하지 않았다. [실행 정책](MARKET_OBSERVATION.md)을 따른다.

## 검증

임시 폴더에서 시각별 상태, 실패/취소/완료, 별도 재시도, 횟수 불일치, 비공개 필드, 부분/큰 로그, 심볼릭 링크, 잘못된 대상/시각, 빈 루트, 목록 상한과 원본 무변경을 확인한다. API의 인증·외부 Origin·query 거부와 실제 로컬 기록의 렌더링도 확인한다. 일반 테스트는 실제 토스 API를 호출하지 않는다.
