# 전략 입력용 시장 데이터 검증

정책 버전: `market-data-v1`. 구현은 `packages/trading/src/market-data`의 순수 함수이며 broker·DB를 참조하지 않는다. worker가 조회 결과와 관측 시각을 조립해 검증한다. 실제 전략·주문 엔진은 아직 실행하지 않는다.

## 봉 종료의 의미

`isClosed=true`는 알고 있는 시장 세션과 대기 시간에 따라 봉 구간 종료 후 다시 관측했다는 뜻이다. 원천 데이터가 영구 불변이라는 보장은 아니다. 미국 늦은 체결과 수정주가에 따른 과거 변경은 가능하며, revision 이력·동결 데이터셋은 후속 작업이다. [토스 공식 FAQ](https://openapi.tossinvest.com/openapi-docs/faq.md)

broker adapter는 계속 모든 원본 봉을 `isClosed=false`로 반환한다. worker에서 각 봉을 `closed`, `pending`, `blocked`로 분류하고 검증한 결과로만 플래그를 다시 설정한다. 입력의 기존 `isClosed` 값은 신뢰하지 않는다. DB에 저장한 플래그만으로 전략 실행을 승인하지 않는다.

## 종료 판정

- 세션이 확인된 동일 시장·거래일의 캘린더가 필요하다. 미제공·휴장·잘못된 세션·중첩·다른 날짜는 차단한다.
- MVP 전략 입력은 정규장으로 제한한다. 시간외 분봉은 화면에 남기되 전략 후보에서 제외한다.
- 1분봉 timestamp는 구간 종료 시각이다. 분 경계·거래일을 검증하고 정규장 시작 이상·종료 이하의 완전한 1분 구간만 취급한다.
- 일반 분봉은 종료 시각 + 60초 이후 재수집해야 한다. 일찍 받아 둔 봉은 시간이 지난 것만으로 종료 상태로 승격하지 않는다.
- NXT 미지원 국내 종목의 정규장 마지막 봉은 최소 16:00 KST, 또는 실제 정규장 종료 + 30분 중 늦은 시각까지 기다리고 60초 뒤 재수집한다. 기본 15:30 봉은 16:01부터 인정한다. NXT 여부가 없으면 해당 경계 봉은 차단한다.
- 일봉 timestamp는 자정 표시이므로 이를 종료 시각으로 사용하지 않는다. 해당 거래일에 제공된 모든 세션이 끝나고 60초가 지나 재수집해야 한다. 미국 일봉 OHLC는 정규장 기준이지만 거래량 집계가 더 넓으므로 마지막 제공 세션까지 보수적으로 기다린다.
- 미국 거래일은 뉴욕 20시 경계를 따르며 분봉 종료 시각의 직전 순간으로 소속 거래일을 판단한다. DST와 조기 폐장은 실제 세션 timestamp를 사용한다.
- 금액 비교는 문자열을 정수 스케일로 맞춘 BigInt로 수행한다. 잘못된 OHLC·음수·미래 시각을 차단하며, 국내 거래량 0 봉을 오류로 간주하지 않는다.

미국 무체결 분의 누락을 임의로 채우지 않으며 분봉 합으로 일봉을 만들지 않는다. 현재 조회 캘린더의 전일/당일/익일 범위에 없는 과거 거래일은 추측하지 않고 미확인으로 남긴다. 장기 과거 데이터에는 별도 날짜별 캘린더 수집이 필요하다.

## 실시간 입력 신선도

| 대상                                  | 기준                                       |
| ------------------------------------- | ------------------------------------------ |
| 시세 원천 timestamp 및 시세 요청 관측 | 120초 미만                                 |
| 계좌 요청 관측                        | 60초 미만, 조회 가능한 BROKERAGE 계좌 존재 |
| 캘린더·캔들 요청 관측                 | 300초 미만                                 |
| 최신 종료 분봉의 구간 종료            | 180초 미만                                 |
| 최신 종료 일봉                        | 현재 캘린더의 직전 영업일                  |
| 환율                                  | `validFrom <= asOf < validUntil`           |
| 현재 거래 시간                        | 정규장 시작 포함·종료 제외                 |
| 미래 관측 시각                        | 실시간 시계 오차 허용 5초, 초과 시 차단    |

관측 시각은 응답을 받은 시각이 아닌 요청 시작 시각을 사용한다. 여러 캔들 페이지는 해당 종목 첫 요청 시각, 여러 계좌는 계좌 조회 시작 시각을 사용하므로 보수적이다. 시각 없는 현재가는 수신 시각으로 대체하지 않는다. 계좌 API에는 원천 갱신 시각이 없으므로 계좌 검사로 증명하는 것은 요청의 신선도뿐이다. 오래된 현재가가 무체결 때문인지 전송 지연 때문인지는 구분할 수 없어 보수적으로 차단한다.

시장·종목·봉 주기·수정주가 여부·source가 다른 데이터나 역순·중복 timestamp를 섞어 전달하지 않는다. 거래정지 및 알 수 없는 국내 거래 가능 정보도 차단한다. KRW/USD 통합 위험 정책이 미정이므로 환율 만료는 양 시장 모두 차단하는 기본값이다.

`prepareStrategyData`는 조건을 모두 만족할 때만 종료 봉 목록을 반환한다. 하나라도 실패하면 `ready=false`, `candles=[]`, 차단 사유를 반환한다. 진행 중 봉은 검사 결과에 남기되 입력 목록에서 제외한다. 이 결과는 전략 warm-up·리스크·소유권·주문 승인까지 충족했다는 뜻이 아니다.

## 결과 표시와 저장

worker는 `dataQuality`에 정책 버전·검사 시각·종목별 종료/대기/제외 개수와 차단 코드를 포함한다. 통과 결과의 `validUntil`은 계좌·시세·환율·캘린더·캔들 신선도 및 정규장 종료 중 가장 먼저 만료하는 시각이다. 대시보드는 그 시각 이후 다시 검증하도록 표시한다. 이전 snapshot과의 호환을 위해 보고서가 없는 경우 미검증으로 취급한다.

`broker:sync`를 명시적으로 실행하면 평가 후의 종료 플래그도 기존 컬럼에 저장한다. 마이그레이션을 추가하거나 자동 적용하지 않는다. snapshot·대시보드 조회는 DB에 시세를 쓰지 않는다. 저장소는 최신 값을 갱신하며 이전 버전·당시 관측 증거의 영속 이력은 아직 없으므로 재현 가능한 백테스트용 동결 데이터로 주장하지 않는다.

## 후속 작업

1. 날짜별 캘린더와 장기 캔들 백필·누락 점검.
2. 관측 증거·revision 이력·동결 데이터셋 저장.
3. 이동평균 교차 전략의 warm-up과 과거 prefix 평가.
4. 수수료·슬리피지·다음 봉 체결을 반영하는 백테스트.
