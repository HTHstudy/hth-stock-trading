## Commission으로 확인되는 것과 빠진 것

`GET /api/v1/commissions`는 **현재 계좌의 시장별 매매 수수료율** 조회다. 계좌 헤더 `X-Tossinvest-Account`와 OAuth 인증을 요구하고, 성공 응답 `result`는 `Commission[]`이다. 요청에 과거 기준일·종목·거래소·매수/매도 구분은 없다. 문서 조사 자체는 실제 계좌 응답을 조회하지 않았다. 이후 주 작업의 정규화된 실제 조회/검토 범위는 [수수료 검토](COMMISSION_REVIEW.md)에 분리해 기록한다.

| 항목           | 명세에서 확인                                                                                                                          | 남는 공백                                                                                                                                                                              |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 요율           | 필수 `marketCountry`, `commissionRate`. 요율은 decimal 문자열인 소수 비율이다. 명세 예시 `0.00015`는 0.015%, 산술상 1.5 bps다.         | 시장당 한 요율 필드이며 매수/매도별 필드는 없다. 양쪽 실제 비용이 같다는 증거는 아니다. 예시는 현재 계좌의 적용 요율이 아니다.                                                         |
| 기간           | `startDate`, `endDate`는 필수가 아니며 nullable인 KST 기준 날짜다. 시작일 설명은 해외주식 null, 종료일 설명은 무기한 적용 시 null이다. | 기간 필드만으로 과거 요율 이력·당시 계좌 자격·프로모션·당시 알려진 정보를 증명하지 않는다. 누락과 명시적 null을 구분하고, 날짜 경계의 정확한 적용 시각/포함 여부도 별도 확인해야 한다. |
| 세금·기타 비용 | `Commission`에는 세금·별도 부과금 필드가 없다.                                                                                         | 누락은 0이라는 뜻이 아니다. KR/US 법정 세율이나 매도 전용 비용을 이 응답에서 추론할 수 없다.                                                                                           |
| 정산 산술      | 반올림/절사·통화별 정산 단위·최소/최대 수수료·건당 고정액·부분 체결 합산 규칙이 없다.                                                  | 요율만으로 실제 청구 금액이나 주문/체결/일별 집계 방식을 재현할 수 없다.                                                                                                               |

소수 비율 × 10000의 bps 변환은 단위 변환일 뿐이다. 현재 응답을 백테스트 설정에 옮겨도 **과거 검증 비용(historical verified)** 으로 승격할 수 없다. 과거 실험에는 해당 계좌·상품·기간·매매 방향의 적용 근거와 당시 정보 가용성, 원문 version/hash가 필요하다. 실제 청구와의 대사는 별도의 정산 증거다.

## 현재 백테스트가 계산하는 것

- 슬리피지를 시가에 적용한 뒤 고정 `priceTick`으로 매수는 올림, 매도는 내림한다. 거래소별 tick 표를 조회하거나 자산 종류·가격 구간·시행일에 따라 tick을 선택하지 않는다.
- 체결대금에 `buyFeeBps` 또는 `sellFeeBps`를 적용하고, 매도에만 `sellTaxBps`를 추가한다. 각 비용을 KRW 1원 / USD 0.01 단위로 **각각 올림**한다. 이는 모델의 선택이며 실제 매수세가 없거나 모든 세금이 매도 bps 하나로 표현된다는 증거가 아니다.
- 최소수수료·고정액·상한·누적 부분 체결 정산은 모델링하지 않으며 합성 전량 체결이다. `Decimal` clone의 기본 `ROUND_HALF_UP` 설정과 별개로 해당 가격/비용 계산은 명시적 `ceil`/`floor`를 사용한다.
- `priceTick`은 통화 최소 단위 이상인 그 배수인지 검사한다. 예제와 KR 테스트의 `priceTick: "1"`은 **고정 KRW 1원 산술 검증**이며 거래소 실제 호가 단위표 준수 검증이 아니다. USD 테스트의 0.01도 실제 모든 상품/거래소의 호가 규칙을 증명하지 않는다.

기존 테스트에는 KR 합성 가격 112/108 및 비용 합계, USD 가격 1.24/1.23 및 센트 올림 기대값이 있다. 이는 코드의 산술 가정을 확인하는 테스트이며 증권사 청구·거래소 적합성 검증이 아니다. 이번에는 테스트를 실행하지 않았다.

## 후속 작업에 필요한 별도 증거

| 증거 종류   | 확보해야 할 범위                                                                                                                                                                                                  |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 계좌 수수료 | 증권사 공식 요율/약관과 변경 이력, 계좌별 적용 자격·기간, 매수/매도·상품·거래 채널별 차이. 현재 조회 snapshot과 과거 근거를 구분한다.                                                                             |
| 세금·부과금 | 관할 공식 근거와 시행일, 자산 종류·거래 장소·매매 방향·과세 기준·면제 조건. Commission을 대체 근거로 쓰지 않는다.                                                                                                 |
| 청구 산술   | 증권사 공식 절사/반올림·최소/최대/고정 비용·정산 통화·부분 체결 집계 정책과 적용일, 개인정보를 제거한 검증 가능한 정산 사례.                                                                                      |
| 실제 tick   | 거래소/규제기관의 공식 규정 및 개정 이력, **자산 종류·거래 장소(venue)·시행일**, 가격 구간·통화·세션/주문 유형 등 규정상 적용 조건, 종목을 해당 규칙에 연결하는 메타데이터. `market=KR/US`만으로 선택하지 않는다. |
| 체결 원천   | 입력 가격의 venue·세션·시각과 적용 규칙의 대응 증거. 기존 문서상 국내 KRX+NXT 통합 가격/거래소 지정 불가, 미국 일부 거래소 원천이라는 제약을 tick 증거만으로 해소할 수 없다.                                      |

이 증거를 확보하기 전에는 현재 설정을 명시적 실험 가정으로 유지한다. KR/US 법정 비용이나 실제 호가 단위표를 추측해 채우지 않으며, 비용/호가 검증을 유동성·체결 가능성·거래 권한 검증으로 확대하지 않는다.

## 이번 확인 범위

로컬 OpenAPI 파싱·version/hash·요청/응답/schema 필드 대조, 엔진·계약·기존 테스트 및 문서의 정적 대조만 수행했다. 새 파일은 이 문서 하나다. 네트워크·인증·DB·주문·시장 규칙 구현·커밋은 수행하지 않았다.

주 작업에서 읽기 전용 수수료 capability와 오프라인 가정 검토 도구를 추가했다. 현재 요율 비교가 가능해졌지만 이 문서의 세금·청구 산술·호가/과거 근거 공백은 그대로다.
