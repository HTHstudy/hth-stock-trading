# Paper 자산 평가 이력

## 표시와 해석

Paper 화면에서 원화·달러별 자산 평가 곡선, 최초 기록 대비 자산 변동률, 최근 5개 평가값을 조회한다. 출처는 합성/실제 시세/미확인으로 구분한다. 실제 시세를 사용해도 Paper 자산이며 실제 증권 계좌의 수익률이 아니다.

평가액은 현금과 해당 통화 보유 종목의 평가액 합계다. 예약 현금은 이미 현금에 포함되어 있으므로 중복 차감하지 않는다. 수동 보유분도 포함하고 통화는 합산하지 않는다. 비용은 체결 후 원장 현금에 반영된 값으로 계산한다.

변동률은 `(기록 자산 - 최초 기록 자산) / 최초 기록 자산 × 100`이며 서버의 십진 연산으로 계산한다. 기준 자산이 0 이하이면 null이다. 최초 기록은 계좌 생성 시점이나 전략 시작 자금과 다를 수 있다. 따라서 화면에는 **최초 기록 대비 자산 변동률**로 표시하고 전략의 누적 수익률로 표시하지 않는다. 시간가중/금액가중 전략 수익률, 자금 유출입 보정, 전략별 성과와 MDD는 후속이다.

과거 기록이 없으면 빈 화면을 제공하고 앞으로의 관측부터 축적한다. 기존 원장의 현재 평가나 체결 내역만으로 과거 시세·자산 곡선을 복원하지 않는다. 조회는 worker 시작·재개·시세 수집·평가 저장을 수행하지 않는다.

## 기록과 정합성

새 테이블 대신 기존 불변 `paper_events`의 ACCOUNT_OBSERVED, PAPER_FILL_RECORDED, ACCOUNT_RECONCILED에 `equityPoint`와 `equityHash`를 함께 저장한다. 값에는 정책 버전, 계좌 원장 version, 출처, 기록/평가 시각, 대사·신선도와 KRW/USD 평가액만 포함한다. 기존 이벤트에 평가 기록이 없으면 과거 값으로 취급하지 않는다.

관측/체결/대사와 같은 트랜잭션에서 기록한다. 기록 실패는 원장 변경도 롤백한다. 체결 replay는 새 이력을 만들지 않는다. 계좌 version 순으로 읽어 timestamp 동률이나 트랜잭션 시작 시각의 순서와 구분한다. 기존 감사 이력의 수정·삭제 방지 정책을 재사용한다. 새 의존성·DB 마이그레이션은 없다.

`GET /v1/paper/equity`는 소유자 인증·localhost·서버 고정 계좌를 요구한다. query parameter를 받지 않는다. 읽기 전용 repeatable-read snapshot에서 최초 기록과 최근 501개를 확인해 최대 500개를 오름차순으로 제공한다. 더 오래된 기록이 있으면 limited=true다. 화면 구간이 제한되어도 변동률 기준은 최초 기록을 유지한다. 계좌별 기존 인덱스와 3초 statement timeout을 사용한다. 대규모 장기 보존을 위한 전용 시계열 인덱스/보존 정책은 후속이다.

각 조회 행과 기준의 strict schema·내용 hash·출처·version 상한/순서를 검증한다. 불일치·저장소 오류는 503 PAPER_EQUITY_UNAVAILABLE로 차단한다. hash는 내용 변경 검사이며 완전성·작성자 공증이 아니다. 계좌 ID·hash·원본 감사 상세·lease token은 응답하지 않는다.

## 화면과 검증

신선도는 기록 당시 원장 평가 기준이다. 과거 신선도 확인이 현재 시세의 신선도를 뜻하지 않는다. 갱신 필요 기록도 저장된 평가값으로 표시하며 경고한다. 그래프는 기록 사이의 새 평가를 생성하지 않는다. 동일 초의 여러 기록은 차트 좌표만 마지막 version으로 묶고 표/API 원본은 유지한다. 시각 퇴행·숫자 범위 문제는 차트를 숨기고 표를 제공한다.

임시 DB와 가짜 시세로 빈 이력, 부분 체결 비용 반영, replay 중복 방지, 계좌 분리, 불변성, 조회 전후 원장 보존, 500개 제한·최초 기준 유지, hash 불일치 차단을 검증한다. API 인증/입력/비공개 필드와 순수 십진 계산·차트 좌표도 테스트한다. 기존 사용자 계좌에 이력을 만들기 위한 Paper 재개나 합성 데이터 주입은 수행하지 않는다.

구현 후 전체 332개 테스트와 타입·린트·빌드·포맷 검사를 통과했다. 화면 렌더링에서 빈 상태·합성 출처·최초 기준·갱신 필요 표시를 확인했다. 로컬 인증 API에서도 기존 원장의 이력이 빈 상태임을 확인했고, 조회 전후 정지/자산 값이 같았다. 사용 중인 Paper DB에 테스트 이력이나 마이그레이션을 적용하지 않았다.
