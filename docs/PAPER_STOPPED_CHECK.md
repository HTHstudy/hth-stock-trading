# 준비 계좌의 정지 상태 시세 점검

2026-11-02 12:00:57–12:00:59 KST에 기존 국내·미국 준비 계좌를 기본 정지/resume=false로 점검했다. 기존 broker 잠금 DB/client의 advisory lock 안에서 시장별로 순차 실행했다. 토큰은 기존 읽기 전용 adapter가 소유하며 실제 계좌/보유분 조회나 주문을 호출하지 않았다. 초기화·마이그레이션·일일 기준 적용·Paper 재개는 실행하지 않았다.

CLI의 ticks=1은 단일 HTTP 요청이나 단일 수집 프레임을 뜻하지 않는다. 시작/복구 프레임과 실제 tick 수집을 구분한다. 미국은 휴장/정규장 밖으로 확인된 구간이며, 오래된 가격으로 계좌 평가 시각이나 일일 손익을 갱신하지 않았다. 반환된 봉이 있어도 현재 전략 입력에 적합한 종료 봉이 있다는 뜻은 아니다.

국내는 데이터 수집과 시장 품질 검사를 통과했지만 계좌 준비 완료가 아니다. 준비 시점의 오래된 account observedAt/reconciled=false와 일일 기준 날짜를 그대로 보존했으며 관측 적용 시 날짜 검사가 차단했다. quote 원천 시각과 DB 평가 시각 차이는 −874ms였고 기존 미래 시각 허용 오차 5초 안이었다. 시각을 현재로 덮어쓰거나 유효 기간/허용 오차를 완화하지 않았다. 이 기록은 해당 수집 시점의 증거이며 이후 새 시세 준비 검사로 대체해야 한다.

## 원장과 일일 기준 검토

조회 전후 checkpoint, 제한된 상태/품질 메타데이터와 비교 artifact는 `.local-data/paper-stopped-checks/f5494d4b-cb70-4658-8357-84889df4ea3b/`에 private 파일로 보관했다. 원본 broker 가격/캔들·인증·실제 계좌 응답을 리포트에 저장하지 않았다. 실행 전후 비교는 두 시장 모두 `incomplete`다. 의도·체결 경로를 실행하지 않았으며 정지 관측을 매매 검증 통과로 표현하지 않는다.

두 계좌의 KRW/USD 일일 기준은 2026-10-30, 기존 netPnl은 모두 0이었다. 점검 당시 목표 거래일은 두 통화 모두 2026-11-02였다. 한도·전략·준비 영수증·현금·빈 보유분·주문/체결 없음은 일치했다. 다만 worker의 정상 lease/복구/정지 이력이 version/epoch를 변경했으므로 최초 초기화 상태 검사(initialControl)는 더 이상 일치하지 않는다. 이를 설정 변경이나 원장 손실로 숨기거나 version을 0으로 되돌리지 않는다. 준비 패널의 initial preparationMatches=false도 이 구분을 따른다.

읽기 전용 `planPaperDayReview`로 음수 손실 이월 정책과 대상일/version이 있는 검토 계획을 작성했다. 계획 작성 전후 snapshot 내용 hash도 보존됐다. 파일은 5분만 유효하므로 다음 적용 직전에 반드시 재생성/재검토한다. 이번에는 acknowledge/apply를 실행하지 않았다. 검토 적용 후에도 정지 상태이며, 실제 시세 준비 확인과 실행 직전 checkpoint 및 별도 명시적 재개가 필요하다.

## 다음 순서

1. 국내는 현재 날짜/version으로 일일 기준 검토 계획을 다시 만들고 손실 이월 정책을 별도로 명시해 적용한다. 기존 손실을 0으로 초기화하지 않는다.
2. 국내를 정지 상태로 다시 관측해 계좌 평가/일일 기준과 시장 데이터의 준비 여부를 확인한다. 기존 실패 기록은 보존한다.
3. 미국은 broker가 확인한 정규장에 다시 점검한다. 새 예약이나 자동 재시도/상시 수집은 이번 작업에서 만들지 않았다.
4. 준비된 계좌의 실행 직전 checkpoint → 명시적 유한 Paper 실행 → 종료 checkpoint/전후 비교를 따른다. 오래된 검사 결과나 만료된 계획을 실행 승인으로 재사용하지 않는다.
