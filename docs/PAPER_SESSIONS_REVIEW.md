# Paper 휴장 대기와 거래일 기준 검토

## 휴장 대기

worker는 시세 수집 후 DB 시각을 기준으로 모든 전략/보유 종목의 시장 캘린더를 확인한다. 현재 거래일·시장·세션의 유효성, 관측 신선도를 검사한다. KR/US 중 하나라도 정규장 밖이거나 확인된 휴장이면 계좌 전체를 보수적으로 대기시킨다. 날짜나 요일만으로 휴장을 추정하지 않는다. 미확인·만료·미래 캘린더, 시세 API 실패는 정상 대기로 숨기지 않고 기존 장애 정지 경로로 종료한다.

첫 대기 전환은 계좌 잠금/lease/epoch 검사를 거쳐 미체결 잔량과 예약을 정리하고 정지·새 epoch·MARKET_CLOSED 이력을 함께 커밋한다. 이미 체결한 현금·수량·원가·평가/일일 손익은 유지한다. quote가 오래됐거나 시각이 없어도 확인된 휴장 중에는 그 가격으로 평가를 갱신하지 않는다. 대기 중 기존 관측 시각을 현재로 바꾸지 않으며 화면의 오래된 평가는 그대로 오래된 상태다.

worker는 lease/heartbeat와 겹치지 않는 수집을 유지하고 `state=waiting`을 보고한다. 반복 대기 때 epoch/정지 이벤트를 중복 증가시키지 않는다. 상시 실행 서비스/장 시작 예약기를 추가한 것은 아니며 CLI의 유한 ticks와 수집 예산을 그대로 따른다. default ticks=1이면 관측 후 종료한다.

**개장해도 자동으로 재개하지 않는다.** 같은 실행기의 상태는 paused로 남고, 신선한 quote로 평가할 수 있을 때만 관측한다. 휴장 중 지정한 --resume을 개장 후에 자동 실행하지 않는다. 다시 실행하려면 기존 worker를 종료하고 최신 데이터/손실 기준을 검토한 뒤 별도 --resume 명령을 사용한다. 긴급 정지나 전략 변경의 epoch는 대기 중에도 우선하며 해당 worker는 종료한다.

## 장시간 중단과 거래일

일일 기준은 서울 00시/뉴욕 20시 모델이다. 연속 관측으로 경계를 통과한 기존 자동 일일 전환은 유지한다. 장시간 중단 뒤 거래일이 달라졌으면 PAPER_TRADING_DAY_REVIEW_REQUIRED로 멈춘다. 휴장 대기를 통해 이 검사를 우회하거나 이전 손실을 0으로 만들지 않는다. KR/US를 한 계좌에 넣으면 두 시장 모두 확인된 정규장이어야 실행할 수 있으므로, 현재 정책에서는 시장별 계좌로 검증하는 편이 맞다.

## 명시적 검토 명령

`paper:day-review`는 *_toss-readonly 출처의 paper-market-_ 계좌와 전용 모의 DB**에만 적용한다. 실제 계좌·현금/수량 변경·주문 생성과 연결하지 않는다. 별도 마이그레이션은 없으며 API/worker 시작으로 검토를 실행하지 않는다. 미확인/합성 계좌에는 적용할 수 없다.

1. worker를 종료하고 미체결 잔량이 정리되었는지 확인한다. 계획 생성은 정지·활성 lease 없음·열린 의도 없음 조건을 요구한다.
2. 계획을 파일로 생성한다. 키/토큰이나 실제 시세 조회가 필요하지 않고 DB를 변경하지 않는다. 파일은 기존 파일을 덮어쓰지 않으며 권한 0600으로 만든다.

```bash
# PAPER_MARKET_DATABASE_URL은 기존 실제 시세 Paper 전용 테스트 DB다.
mkdir -p .local-data
corepack pnpm paper:day-review --account=paper-market-local --output=.local-data/day-review.json
```

3. 파일의 계좌·출처·이전 일일 손익·적용 대상 거래일과 정책을 확인한다. 계획은 5분 동안만 유효하다. 정책은 다음과 같다.

- 거래일이 달라진 통화는 `min(이전 일일 손익, 0) + 새 평가액 - 이전 평가액`을 새 기준으로 사용한다.
- 같은 거래일인 통화는 기존 일일 손익에 평가 차이만 더한다.
- 이전 손실은 이월하고 이전 거래일의 이익은 새 손실 한도를 넓히는 데 사용하지 않는다. 가격 변동에 따른 실제 모의 평가 차이는 반영한다.
- 공백 기간의 손익을 날짜별로 재구성하지 않는 보수적인 모의 모델이다. 예를 들어 이전 -500, 평가 차이 -100이면 새 값은 -600이다. 이전 +500, 평가 차이 -100이면 새 값은 -100이다. 검토 파일 생성 시점에는 새 가격을 읽지 않으며 최종 평가 차이는 승인 시 신선한 quote로 계산한다.

4. 정책을 확인한 경우에만 별도 명시적 승인 명령을 사용한다. 승인에는 기존 DATABASE_URL의 같은 client 토큰 잠금과 서버 키 설정이 필요하다. 보유분이 있다면 읽기 전용 현재가를 조회하며 가격을 직접 입력/덮어쓰는 옵션은 없다.

```bash
corepack pnpm paper:day-review --account=paper-market-local \
  --apply=.local-data/day-review.json --acknowledge=CARRY_FORWARD_PAPER_LOSSES
```

승인은 source·정지·계획 만료/대상 날짜·이전 손익·계획 version을 검사한다. lease 획득 시 CAS로 다른 정지·설정 변경·관측을 검출한다. 검토 중에는 단일 token 잠금을 유지하고 보유분 전체의 신선한 quote·시각 퇴행·통화/수량 집합을 검사한다. 수집은 10초 한도이며 이후 원장 version·lease/epoch·대상 날짜·열린 의도를 다시 검사한다. 모든 평가/손익 변경과 이전/이후 감사 이력은 같은 트랜잭션이다.

성공해도 **정지 상태**이며 lease를 해제한다. 자산 소유권·현금·수량·원가·주문/체결은 변경하지 않는다. 전략 재개는 별도 기존 절차다. 실패 시 일일 손익을 변경하지 않으며, lease 획득 이후 실패했다면 계획 version이 달라지므로 새 계획이 필요하다. 원본 오류·파일 내용·가격·계좌 번호는 로그에 출력하지 않는다.

계획/승인은 현재 CLI에만 제공한다. 브라우저 승인·자동 승인·스케줄러·장시간 실제 시세 운용 검증은 후속이다. 테스트에서는 전용 임시 DB와 가짜 시세만 사용하며 개발 중 실제 계좌의 검토 승인이나 Paper 재개를 실행하지 않는다.

거래 없이 시장 세션/지연을 장시간 점검하는 명령은 [시세 관측과 운영 리포트](MARKET_OBSERVATION.md)를 따른다. 이 관측으로 거래일 검토를 승인하거나 Paper를 재개하지 않는다.
