## 주문 의도가 없었던 이유

기존 전용 DB의 read-only snapshot에서 before/after 진단 이벤트 집합 전체를 읽고 schema/hash·출처·설정/시각·이벤트 연결을 검증했다. 결과는 저장된 판단 **22건 전부 strategy 단계의 HOLD / NO_CROSS**였다. BUY·SELL·미평가 기록은 각각 0이다.

- 기록 평가 구간: 00:05:04.260~00:15:35.559 KST.
- 서로 다른 확정 봉 시각: 11개, 00:04~00:14 KST.
- 준비된 확정 봉: 34~44개. MA 5/20에 필요한 21개보다 많았다.

- 기록의 전략 버전은 1.0.0, revision은 하나이며 before/after strategy hash도 같았다.

조회 전후 Paper 원장 hash와 정지/lease 없음이 유지됐다. broker·토큰·시세 재조회·전략 재평가·주문·DB 마이그레이션은 수행하지 않았다. 진단을 만들기 위해 전략/한도를 변경하거나 합성 신호를 주입하지 않았다.

## 자료와 표시 경계

원본 실행 폴더와 owned launch/exit는 기존 파일을 보존했다. 진단 파일을 원본 실행 폴더에 추가하는 시도는 자동 승인 검토에서 거부되어 실행되지 않았고, 대안으로 DB 자료를 메모리에서만 집계했다. `diagnostics.json`은 추가하지 않았다. 따라서 현재 웹의 구간 진단은 이 문서의 집계와 달리 연결된 진단 자료 없음으로 보일 수 있다. HTTP 조회를 DB 접근이나 파일 생성으로 확장하지 않는다.
