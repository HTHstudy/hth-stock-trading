# 실제 시세 Paper 검증 계획

이번 1차 검증에 사용할 별도 계획은 [검증 설정 v1](PAPER_VALIDATION_SETTINGS.md)에 정리했다. 아래 기존 예제·기본값은 보존하며 새 계획을 기존 계좌에 자동 적용하지 않는다.

기존 `paper:market --initialize`의 가상 자금·한도·전략 기본값을 명시적인 JSON으로 검토할 수 있다. 새 계획은 **개발 검증용 제안**이며 투자 전략이나 실제 주문 승인이 아니다. 계획을 미리 보는 것만으로 DB·broker·관측·현재 계좌를 변경하지 않는다.

## 미리보기

```bash
corepack pnpm paper:plan --plan=examples/paper-market-kr-plan.json
corepack pnpm paper:plan --plan=examples/paper-market-us-plan.json
```

두 계획은 시장별 새 계좌 검증을 위한 예시다. 국내 계획은 KRW 1,000,000/USD 0, 미국 계획은 KRW 0/USD 1,000의 **가상 현금**만 사용한다. 실제 계좌 잔고·보유 주식을 복사하지 않는다. 이동평균 5/20, 주문 1주, tick당 최대 체결 1주다. 종목은 기존 연결 검증에 쓰던 KR:005930/US:AAPL이며 관심종목이나 실제 전략 설정을 바꾸지 않는다.

한도는 기존 코드의 기본값을 유지한다. KRW 주문 100,000/종목 200,000/일손실 10,000, USD 주문 100/종목 200/일손실 10, 최대 5종목이다. 비용은 매수 10bps/매도 30bps의 합성 가정이다. 실제 수수료·세금·수익성을 뜻하지 않는다. 양 통화 한도를 요구하는 기존 계약 때문에 미사용 통화에도 한도가 있지만 현금 0이며 자동 환전하지 않는다.

미리보기는 현재가·매수 가능 여부를 조회하지 않는다. 예를 들어 1주 가격과 비용이 주문 한도를 넘으면 실제 시세 Paper에서 리스크가 거부한다. 통과시키기 위해 한도를 자동 상향하지 않는다. 전략이나 가상 예산을 바꾸려면 JSON을 명시적으로 수정하고 다시 미리 본다.

출력에는 정규화된 계획과 `planHash`, 별도로 필요한 관측 검토·정지 상태 관측·일일 손실 검토·명시적 Paper 재개 항목이 있다. 이것은 해당 항목의 통과 결과가 아니다. 기본 실행 정책은 계속 paper이고 실제 주문은 비활성이다. `.env`·키·DB 없이 실행하며 `TRADING_MODE=live`를 거부한다.

## 새 계좌 초기화에 연결

실제 시세 관측 결과와 검증 조건을 검토한 뒤에만 별도 테스트 DB에서 실행한다. 아래 명령은 절차 예시이며 이번 개발에서는 실행하지 않았다. `PAPER_MARKET_DATABASE_URL`과 토큰 잠금용 `DATABASE_URL`, 키 설정은 [기존 실행 문서](PAPER_MARKET_SOURCE.md)를 따른다.

```bash
# 미리보기에서 확인한 64자리 해시를 HASH 자리에 넣는다.
corepack pnpm paper:market --account=paper-market-new-kr --initialize \
  --plan=examples/paper-market-kr-plan.json --plan-hash=HASH
```

필요한 전용 테스트 DB 최초 마이그레이션은 위 초기화 명령에 `--prepare`를 추가할 수 있다. 사용자 업무 DB를 사용하지 않는다. 이 명령은 새 계좌를 **정지 상태로** 초기화하고 기본 1회 관측 후 종료한다. 시장이 닫혔으면 기존 휴장 대기 정책을 적용하며 오래된 가격으로 평가하지 않는다. 재개는 기존 별도 `--resume` 절차로만 가능하다.

`--plan`은 `--initialize`와 확인한 `--plan-hash`를 함께 요구한다. `--symbol`, `--stop`, `--resume`와 결합할 수 없다. 기존 계좌 적용·재초기화·재개 시 계획 덮어쓰기를 거부한다. 기존 계좌는 DB에 저장된 전략·한도를 사용하며 변경은 기존 전략 관리 절차를 따른다.

계획은 한 번 읽은 내용을 사용하고, strict schema와 SHA-256을 DB 연결 전 및 실행기 진입 시 검사한다. 검토 후 내용이 바뀌면 `PAPER_MARKET_PLAN_HASH_MISMATCH`로 마이그레이션·계좌 생성·broker 잠금/생성 전에 차단한다. 공백/키 순서만 바뀐 동일한 JSON은 같은 hash다. 해시는 승인 서명·실시간 매매 허가가 아니며, 자동으로 관측 리포트를 검토하거나 일일 손실 기준을 승인하지 않는다.

상대 경로는 저장소 루트를 기준으로 해석한다. 일반 파일·64KiB 이하만 읽고 알 수 없는 필드·다른 출처·실거래 모드·지원하지 않는 전략 버전·KRW 소수 현금·USD 2자리 초과 현금·200봉 페이지 예산을 넘는 장기 기간을 거부한다. 오류 로그는 파일 원문이나 경로를 포함하지 않는다. 계획에는 비밀 정보를 넣지 않는다.

## 호환성과 이력

계획 없이 초기화하던 명령은 기존 가상 현금·한도·전략 기본값을 유지한다. DB 스키마와 기존 계좌는 바뀌지 않는다. 계획 적용 시 CLI는 계획 hash를 남기며, 실제 저장된 한도·전략·설정 변경 이력은 기존 원장에 기록한다. 계획 JSON 전체나 hash를 새 DB 열에 별도 보관하지는 않으므로, 계획 파일과 실행 로그도 검증 증거로 보존한다. 초기화가 여러 트랜잭션인 기존 제약은 유지하며 중간 실패로 정지된 불완전 계좌가 남으면 자동 덮어쓰지 않는다.

현재 단계는 계획 도구와 가짜 broker/전용 DB 검증이다. 시장 관측 완료, 실제 시세의 장시간 Paper 운용, 실거래 또는 배포는 별도 단계다. 합성 엔진 검증은 [Paper 통합 리허설](PAPER_REHEARSAL.md)과 구분한다.

## 검증 기록

2026-10-30 별도 임시 PostgreSQL에서 전체 400개 테스트를 통과했다. 새 계좌에 맞춤 가상 현금·한도·전략이 저장되고 정지 상태·열린 lease 없음·주문 없음이 유지되는 것을 확인했다. 기존 계좌 재초기화 거부, 변경/누락된 계획의 I/O 이전 차단, KR/US CLI 미리보기도 확인했다. 실제 broker 대신 fixture를 사용했으며 기존 계좌 재개나 실주문을 수행하지 않았다.
